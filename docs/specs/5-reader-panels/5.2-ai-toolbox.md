## Summary

On-selection AI tools — translate, explain, etymology — that stream an answer about the selected
text without leaving the page. The product's core "investigate in flow" job.

## Scope

- In: translate (to user's target lang), explain, etymology; every tool's prompt is enriched with
  book context — the sentence(s) containing the selection plus the previous sentence, and the book
  title + author; streaming output with typewriter effect, retry, expand saved results;
  copy-selection and expandable exact-selection preview.
- Non-goals: free-form chat (future ai-chats), full-book narration, generating standalone highlights.

## Behaviour

1. Select text → toolbox panel offers the three tools.
2. Run or retry a tool → save its intent in the existing per-account AI comments bucket first, then
   stream the result through bucket sync. Slow connections and unavailable Clerk state never reject
   a remembered reader as signed out; requests stay cached across navigation/reload and resume
   automatically with a valid same-account session when connectivity/authentication recover.
3. Results are saved as AI comments anchored to the selection; reopening expands tools that already
   have results.
4. Offline, unavailable auth or no response headers within 5s → queued “waiting for connection”.
   Retry/backoff restores streaming when connected. The header timeout does not cut an active body
   stream; a mid-stream idle stall is still an open question.
5. Every generate request carries the selection's context when it can be derived: the sentence(s) of
   the start block overlapping the selection plus the sentence before (falling back to the last
   sentence of the nearest preceding text block; omitted at chapter start), whitespace-collapsed.
   Over the length cap it is cut from the beginning — the tail nearest the selection's own sentence
   survives, the previous sentence is sacrificed first. Book title and authors ride along. The model
   is instructed to use these for disambiguation only — it still translates/explains/analyzes just
   the selection.
6. The selection strip's Copy button writes the exact selection text to the clipboard. Success is
   announced to assistive technology, with no toast; re-copying restarts the confirmation.
   Client-only, nothing persisted.
7. The selection preview can expand to reveal the exact full fragment and collapse again. A new
   selection resets it to collapsed. This is client-only; `aria-expanded` reflects the state.

## Shared response language

TOOL-TRANSLATE-01: Translate the exact selected text, including a single word or literal placeholder.
Infer source usage from the selection and sentence; book metadata never makes it missing content.
Always submit to the model; column language cannot prove a fragment's language. When already in
the target language, return it unchanged, preserving selected quotes. Output contains only translation,
without requests for another passage, explanations or conversational refusals.

TOOL-LANG-01: “Translate to” is one account preference shared by Toolbox and Preferences, with the
same complete language list. Translation, Explain and Etymology all use that response language.
Changing it keeps open tools open, hides prior-language output immediately and queues generation
for the new language unless a matching result already exists. Statuses remain language-specific
through queued, streaming, ready, failed and retry states; old-language chunks cannot replace them.
Capture language/context/locator in durable intents and deduplicate on the full request identity.
Preserve prior-language results as separate saved comments; legacy results without a language do not
satisfy a newly selected response language. A retry with a tied timestamp supersedes its old attempt.

TOOL-FACT-01: Response language changes prose, never the source setting, historical entities or
meaning. Explain named references as whole expressions in their book context; do not invent history,
character-by-character origins or symbolic intent. State uncertainty instead of filling gaps.
Completed results offer Regenerate, durably queued with a fresh idempotent generation identity so
an incorrect saved/server-cached answer can be replaced without deleting prior annotations.

## Context and narration

The selection action also offers [temporary word/phrase narration](5.6-selection-narration.md),
funded by AVA through OpenRouter (Google Flash TTS trial). Sentence context identifies its spoken language.
It saves no AI comment and does not queue offline playback.
The translation speaker reads completed displayed translations up to 2,048 characters, with their
known output language only for exclusive scripts; shared-script/preserved foreign names use context
with the original selection and book metadata. Longer output has explicit unavailable feedback. It
shares the player’s
loading/playing/stop/error lifecycle. It is unavailable while generation is pending
or failed. Collapsing the tool or changing selection/language stops it; only one clip plays at once.

Pure helpers derive context from chapter blocks and locators with `Intl.Segmenter`. Fresh selection,
existing highlights and AI-comment marks share this path; durable intents capture the result before
replay. The exact selected text remains the task; context is only supporting evidence.

## Data & sync

Backed by the ai-comments bucket via generate.{translate|explain|etymology} mutations → POST
/library/:itemId/ai-comments/{translate|explain|etymology} → streamed structured output stored as a
ready Ai Comment. All three payloads accept optional `context`, `bookTitle`, `author` (previously
explain only). Target language from UserPreferences. The comment's status (queued → streaming →
ready, or failed-with-reason) is the single source of truth the panel renders from.

Server cache key (sourceHash) is hash(kind | text | targetLang | model | context | bookTitle |
author | prompt | regenerationId) — context-bearing requests no longer collide across locations or books (previously the same
phrase served one cached answer everywhere, leaking book A's explanation into book B). Old cache
rows survive as saved comments; no migration. Prompt changes invalidate server reuse. Explicit
regeneration IDs produce fresh answers while reconnect replay of the same ID remains idempotent.

## Edge cases

Offline generation stays queued. Transient failures retry; permanent4xx retain a failed row with
its reason and Try again inline. Delete failures toast. Body streams have no idle timeout; genuine
mid-stream drops retry. Missing API/credit key: see ADR3. Context degrades to none when locator,
chapter/text blocks or Intl.Segmenter are unavailable. Requests without
context/bookTitle hash like legacy ones, so cross-book cache sharing can still occur only on that
degraded path. Copy: clipboard API unavailable or the write rejects → error feedback; empty
selection no-ops.

## Acceptance criteria

- [ ] Each tool returns a streamed result for a selection and persists it.
- [ ] Translate respects the configured target language.
- [ ] A tool run offline, on a slow connection, or while Clerk is unavailable is durably queued and
      completes after connectivity and same-account authentication recover.
- [ ] A generate request that gets no response within 5s is aborted and queued for retry — the panel
      shows the "waiting for connection" placeholder, not an indefinite "Generating…" animation, and
      the result appears automatically once a retry succeeds.
- [ ] A generate request that does get a response within 5s is never aborted mid-stream by the
      timeout, however long the stream itself takes.
- [ ] A permanent failure shows the server reason inline with a Try again button (no toast); retry
      re-runs and succeeds once the cause is resolved.
- [ ] All three tools send context (containing + previous sentence), bookTitle, and author when
      derivable; the prompts include them with use-for-disambiguation-only instructions.
- [ ] A selection with no derivable context still generates exactly as before (fields omitted).
- [ ] Different contexts, prompts and explicit regenerations cannot reuse stale answers.
- [ ] Copy confirms success only after a successful write; preview expansion preserves selection.

## Open questions

Per-user key/credit enforcement, rate limiting, full saved-result versioning and mid-stream idle
timeout. Only genuine connection drops currently retry after headers.
