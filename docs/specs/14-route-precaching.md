# Route precaching (offline app shell)

> Status: active · Updated: 2026-06-11 · ADRs: [[3-offline-first-dexie-buckets]], [[4-route-precaching-service-worker]] · Related: [[11-cache-priming]], [[6-offline-reading]] · Code: apps/web/public/sw.js, apps/web/scripts/gen-precache-manifest.mjs, apps/web/features/offline/{prime/routes,prime/prime-routes,sw/precache-routes}, apps/web/components/app/core/route-precache-runner.tsx

## Summary
Make every app route load offline — including hard reload and direct-URL entry — after a single online visit to any one route. Caches the route *shell* (HTML doc + RSC payload + JS/CSS chunks); data still comes from Dexie buckets. Serves the offline-first job (product.md).

## Scope
- In: a build-time asset manifest the SW precaches; a `PRECACHE_ROUTES` SW message an AppShell island sends with the static routes + one `__shell__` sentinel per per-entity family (reader, book-info, collection — generic shells per [[4-route-precaching-service-worker]]); per-family doc fallback for offline navigations.
- Non-goals: caching book *content* (owned by [[6-offline-reading]]/[[11-cache-priming]]); executing pages; freshness of precached shells (reactive network-first still refreshes on later online visits); per-book doc/RSC precaching (dropped — see ADR 4).

## Behaviour
1. **Build:** a post-build script globs `.next/static/**/*.{js,css}` → `apps/web/public/precache-assets.json` (overwritten each build). Wired into the `build` script after `next build`.
2. **Asset precache:** on `activate`, the SW fetches that file (`no-store`) and caches every listed URL into the versioned cache, so no route is missing chunks offline. A SW's own `fetch()` bypasses the fetch handler, so no filename versioning is needed — eviction rides the existing version-named cache.
3. **Route precache:** an AppShell island (mounted on *any* `/app` route; while online) posts `{type:"PRECACHE_ROUTES", routes}` to the active SW. `routes` = the static app routes (`/app`, `/app/library`, `/app/insights`, `/app/explore`) + one `__shell__` sentinel per per-entity family (`/app/read/__shell__`, `/app/library/books/__shell__`, `/app/library/collections/__shell__`) — those pages are generic shells (ADR 4), so any slug returns the same document. No library-view dependency; ~7 fetches total. The island is **stateless** — it re-runs once per page-session and on SW takeover (`controllerchange`), not gated by a persisted flag.
4. **SW handling:** for each route the SW fetches the document (plain GET) and the RSC payload (`RSC:1` header), storing them under the existing `__sw=doc` / `__sw=rsc` keys, query params stripped. Per-entity-family docs are *additionally* stored under the family's `__shell__` key (every successful doc fetch refreshes it). Bounded concurrency; failures skipped (best-effort), 3xx/redirects not cached. Already-cached routes are skipped, so re-posting is cheap.
5. **Offline serving (docs):** exact per-URL match first, then the per-family `__shell__` fallback — so a never-visited book still gets the shell, which hydrates the right book from `location.pathname` + Dexie. **RSC:** strictly per-URL, no cross-slug fallback (a mismatched payload risks Next rewriting the URL); a failed RSC fetch triggers Next's built-in hard navigation, which lands on the doc path.
6. A new build installs a fresh SW + asset set and evicts the old cache (existing activate logic); `controllerchange` re-runs the island so the new version's route shells are precached.

## Data & sync
No new buckets/endpoints, **no bookkeeping flag** — re-running is idempotent (the SW skips already-cached routes), so precaching is driven purely by the session/`controllerchange` triggers rather than a persisted "done" marker (which would lock out new builds). The route list is fixed (static + sentinels) — no Dexie reads. Cache keys + eviction reuse apps/web/public/sw.js.

## Edge cases
Offline when the island runs → skipped, retried on reconnect/next route. SW not yet active → island awaits `navigator.serviceWorker.ready` before posting. SW update mid-session → `controllerchange` re-runs the island against the new cache. Auth-gated doc fetch returns a Clerk 3xx → not cached (existing `ok`-only guard). Never-visited book offline → family shell serves; whether it *reads* depends on its content being in Dexie ([[6-offline-reading]]/[[11-cache-priming]]) — missing content shows the missing-book modal, not a network error. Book added on another device → shell already covers its routes; only its content needs priming.

## Acceptance criteria
- [ ] After one online visit to any app route, a hard reload or direct-URL entry of *any* reader/book-info/collection route — including never-visited books — serves a document offline (content gated only by Dexie).
- [ ] `precache-assets.json` is generated by the build and lists all `/_next/static` JS/CSS.
- [ ] Route precache runs per page-session and re-runs on SW takeover, yields when offline, and never executes page side effects (no auto-save/reading-session triggered by precaching).
- [ ] A new build installs a fresh SW that evicts the previous version's asset + route caches.

## Open questions
