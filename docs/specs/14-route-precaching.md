# Route precaching (offline app shell)

> Status: active · Updated: 2026-07-01 · ADRs: [[3-offline-first-dexie-buckets]], [[4-route-precaching-service-worker]] · Related: [[11-cache-priming]], [[6-offline-reading]] · Code: apps/web/public/sw.js, apps/web/scripts/gen-precache-manifest.mjs, apps/web/features/offline/{prime/routes,prime/prime-routes,sw/precache-routes}, apps/web/components/app/core/route-precache-runner.tsx

## Summary
Make every app route load offline — including hard reload and direct-URL entry — after a single online visit to any one route. Caches the route *shell* (HTML doc + RSC payload + JS/CSS chunks); data still comes from Dexie buckets. Serves the offline-first job (product.md).

## Scope
- In: a build-time asset manifest the SW precaches; a `PRECACHE_ROUTES` SW message an AppShell island sends with the static routes + one `__shell__` sentinel per per-entity family (reader, book-info, collection — generic shells per [[4-route-precaching-service-worker]]); per-family doc fallback for offline navigations.
- Non-goals: caching book *content* (owned by [[6-offline-reading]]/[[11-cache-priming]]); executing pages; freshness of precached shells (reactive network-first still refreshes on later online visits); per-book doc/RSC precaching (dropped — see ADR 4).

## Behaviour
1. **Build:** a post-build script globs `.next/static/**/*.{js,css}` → `apps/web/public/precache-assets.json` (overwritten each build). Wired into the `build` script after `next build`.
2. **Asset precache:** on `activate`, the SW fetches that file (`no-store`) and caches every listed URL into the versioned cache, so no route is missing chunks offline. A SW's own `fetch()` bypasses the fetch handler, so no filename versioning is needed — eviction rides the existing version-named cache.
3. **Route precache:** an AppShell island (mounted on *any* `/app` route; while online) posts `{type:"PRECACHE_ROUTES", routes}` to the active SW. `routes` = the static app routes (`/app`, `/app/library`, `/app/insights`, `/app/explore`) + one `__shell__` sentinel per per-entity family (`/app/read/__shell__`, `/app/library/books/__shell__`, `/app/library/collections/__shell__`) — those pages are generic shells (ADR 4), so any slug returns the same document. No library-view dependency; ~7 fetches total. The island posts, then **awaits the SW's completion ack** (all reachable shells cached) — it does not treat "message posted" as done. It re-runs on SW takeover (`controllerchange`) and **on every reconnect until a pass is confirmed complete**, so a pass interrupted by going offline is retried, never latched done at post time. A confirmed pass sets the in-session **shells-ready** signal the readiness cue consumes ([[11-cache-priming]]).
4. **SW handling:** for each route the SW fetches the document (plain GET) and the RSC payload (`RSC:1` header), storing them under the existing `__sw=doc` / `__sw=rsc` keys, query params stripped. Per-entity-family docs are *additionally* stored under the family's `__shell__` key (every successful doc fetch refreshes it). Bounded concurrency; 3xx/redirects not cached. Already-cached routes are skipped, so re-posting is cheap. When the pass settles the SW **replies with the set of routes now cached**, so the client can tell whether offline browsing is genuinely ready or must be retried on reconnect.
5. **Prefetch bypass (reactive fetch handler):** Next marks link prefetches with a `next-router-prefetch` (or `next-router-segment-prefetch`) header; real navigations carry `next-router-state-tree` instead. A dynamic route *with* a `loading.tsx` (e.g. `/app/library`) prefetches to a tiny "loading" **stub**, not the full page. The SW **must not** cache or serve prefetch responses under the shared navigation key: caching one overwrites the full precached RSC, and offline that stub is a valid `200` that Next neither finishes rendering *nor* falls back from (no hard-nav) — the route is stranded with the URL changed and the previous page still shown. So any request carrying a prefetch header passes straight through to the network (no cache read/write); the navigation key keeps the full payload the precache / a real navigation stored.
6. **Offline serving (docs):** exact per-URL match first, then the per-family `__shell__` fallback — so a never-visited book still gets the shell, which hydrates the right book from `location.pathname` + Dexie. **RSC:** strictly per-URL, no cross-slug fallback (a mismatched payload risks Next rewriting the URL); a failed RSC fetch triggers Next's built-in hard navigation, which lands on the doc path.
7. A new build installs a fresh SW + asset set and evicts the old cache (existing activate logic); `controllerchange` re-runs the island so the new version's route shells are precached.

## Data & sync
No new buckets/endpoints and **no *persisted* done marker** (it would lock out new builds — a fresh SW starts with an empty cache). Instead an **in-session** completion state, set on the SW's ack, drives the shells-ready signal and stops the reconnect retries; it resets on `controllerchange`. Re-running stays idempotent (the SW skips already-cached routes). The route list is fixed (static + sentinels) — no Dexie reads. Cache keys + eviction reuse apps/web/public/sw.js.

## Edge cases
Offline when the island runs → skipped, and retried on every reconnect until the SW acks a complete pass (an interrupted or partial precache is never marked done — the post-time latch that stranded the library shell is the bug this closes). SW not yet active → island awaits `navigator.serviceWorker.ready` before posting. SW update mid-session → `controllerchange` re-runs the island against the new cache. Auth-gated doc fetch returns a Clerk 3xx → not cached (existing `ok`-only guard). Never-visited book offline → family shell serves; whether it *reads* depends on its content being in Dexie ([[6-offline-reading]]/[[11-cache-priming]]) — missing content shows the missing-book modal, not a network error. Book added on another device → shell already covers its routes; only its content needs priming. Online link prefetch of a `loading.tsx` route (`/app/library`) → bypassed, so its partial "loading" stub can't poison the navigation key; the precache's full `rsc:1` fetch stays the offline payload. (This was the bug behind "URL flips to `/app/library` but the page stays on home": the poisoned stub was served, so the navigation neither completed nor hard-fell-back to the cached doc.)

## Acceptance criteria
- [ ] After one online visit to any app route, a hard reload or direct-URL entry of *any* reader/book-info/collection route — including never-visited books — serves a document offline (content gated only by Dexie).
- [ ] `precache-assets.json` is generated by the build and lists all `/_next/static` JS/CSS.
- [ ] Route precache runs per page-session, re-runs on SW takeover **and on reconnect until the SW confirms a complete pass**, yields when offline, and never executes page side effects (no auto-save/reading-session triggered by precaching).
- [ ] A new build installs a fresh SW that evicts the previous version's asset + route caches.
- [ ] After the "Ready for offline work" cue ([[11-cache-priming]]), a hard reload or navigation to any static route offline serves its shell — no black/unreachable page — because the cue waits on the SW's precache ack.
- [ ] A Next link **prefetch** never overwrites a route's cached navigation RSC. Offline soft-navigation to `/app/library` (the one static route with a `loading.tsx`) serves its full shell — not a partial prefetch stub — so the page renders instead of stranding on the previous route.
