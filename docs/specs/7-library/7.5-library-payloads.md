# Library · payloads (server)

> Status: shipped · Updated: 2026-08-30 · Parent: [[_overview]] · Code: apps/api/src/library

## Summary
The server reads behind the library UI: the two-phase overview, collection and book-info reads,
and the public cover endpoint. Every book list serializes the shared card shape ([[_overview]]).

## Behaviour
1. GET /library — two phases. Phase 1 pulls collections plus a lightweight view of every item
   (ids, archived flag, engagement dates, completion) — enough for counts and the engagement
   sort without touching book metadata or cover bytes (the historical hot path that made library
   loads slow). Phase 2 fetches full book detail only for each collection's first 4 active items
   (the preview cards). itemCount and unreadCount (completion < 100) cover all active items.
   summary.booksCount counts the books on the two source shelves (Imported Books, Public Domain),
   which together hold every book exactly once; an absent shelf is skipped and repeats dedupe.
   Offline Books and custom lists re-list those same books, so counting them too would inflate
   the total. collectionsCount is the collection total.
2. GET /library/collections/:ref (id or slug) — the full collection with all active books,
   engagement-sorted, in the same summary shape as the overview sections.
3. GET /library/:ref (id or slug) — the book-info payload: metadata, approximate page counts,
   progress fields, the item's collections (sorted sortOrder then name), primaryFormat.
4. PATCH /library/:ref/offline — sets offlineRequested and syncs Offline Books membership in one
   transaction ([[12-offline-save-sync]], [[17-offline-books-collection]]).
5. GET /library/covers/:bookId — public, unauthenticated, long-lived Cache-Control: covers are
   not sensitive, ids are unpredictable CUIDs, and `<img>` tags skip Clerk token juggling. Cover
   bytes are never inlined in payloads — cards carry this URL instead.
6. primaryFormat is the primary SOURCE file's format (a processed book also carries a primary
   DERIVED_READER file — kind disambiguates). Archived items are excluded everywhere.

## Edge cases
Unknown ref or another user's item/collection → 404; missing cover → null coverImageUrl and 404
from the cover endpoint; empty library → empty collections and zero counts.

## Known gaps
booksCount comes from the source shelves, so an active item missing from its shelf — or held
only by a custom list — goes uncounted. Unreachable today: every added book joins the shelf
matching its source ([[7.3-collections]] §2).
