# Library · screen

> Status: shipped · Updated: 2026-08-30 · Parent: [[_overview]] · Code:
> apps/web/components/app/library, apps/web/features/offline/buckets/library

## Summary
The library page: every collection as a section of book cards, backed by the library bucket and
the GET /library snapshot ([[7.5-library-payloads]]).

## Behaviour
1. Library lists the user's books with progress; clicking a card opens book-info or the reader.
2. Each collection renders as a section: title, a preview of up to 4 cards, and "View all". The
   section title links to the collection page (same target as its "View all" link), styled like
   the plain heading; on hover it shifts to ink, matching the book-card title hover.
3. Sections order by the engagement recency of their most recent active item, then by fewest
   active items, then by name; a collection with no active items sorts last. Two collections tie
   on recency when their most recent book is *the same book*: a broad shelf re-lists a narrow
   shelf's books, so opening one gives every collection holding it a byte-identical timestamp and
   the item count is what actually separates them, floating the more specific shelf up. That is
   the common case, not the exception. Within a section, cards order by engagement recency
   ([[_overview]]); archived items never render.
4. Metadata is cached for offline; revalidates against server updatedAt when online.
5. The header's Books metric is the library-wide count of unique books
   ([[7.5-library-payloads]]): a book on several shelves (also in Offline Books, or a custom
   list) counts once. The payload carries the number and the cache stores it — the screen never
   re-derives it from cached rows, which hold only the per-collection preview subset.
6. The header bar pairs each metric with its action. Below md it is a two-column grid — one row
   per metric, its button leading in column one and the count following, both buttons sharing
   that column so they match width:
   Collections → "New collection" (primary), Books → "Import new book" (soft, [[7.4-import]]).
   From md up the single row keeps search, both metrics, then the two buttons right-aligned with
   Import before New collection. "New collection" is inert until collection create has an
   endpoint ([[7.3-collections]]).
7. Import's status message ("… imported", "Upload failed") renders out of flow, absolutely
   positioned under its button. The button's box must not change size when the message appears:
   in the md row the actions are vertically centred, so a message that grew the button's column
   would shift the button upward. Nothing reserves a blank line for it either.
8. A successful import refreshes the list in place, without a manual reload. The screen reads
   the library bucket once hydrated and ignores a re-rendered RSC payload, so import revalidates
   the bucket against GET /library itself; the router refresh it also triggers is what updates
   the RSC-only surfaces (home). The new book is on screen by the time the "Uploading…" label
   clears.

## Data & sync
library bucket (items + collections + membership, normalized). GET /library snapshot;
revalidation skips unchanged fetches.

## Edge cases
Offline browse from cache; empty library/collection states. Long titles clamp to two lines and
never widen the card: the card's column track is minmax(0,1fr), so a title word wider than the
column (e.g. "Communication:" on a phone-width grid) overflows hidden instead of pushing the
cover past its grid column. The library list tolerates an unreachable API or an unverifiable
(stale, Clerk-offline) session — `fetchServerApiTolerant` returns null → renders
`LibraryScreenFromCache` rather than the error boundary. Below ~340px the longer action label
wraps to two lines, so the paired buttons stop matching height — nothing overflows. Offline
Books is derived client-side from offlineRequested ([[17-offline-books-collection]]), so both
of its ordering keys are recomputed locally alongside its counts — the server's numbers
describe the last synced membership.

## Acceptance criteria
- [ ] Library renders offline from cache.
- [ ] Each section previews at most 4 books; itemCount/unreadCount reflect all active items.
- [ ] The Books metric counts a book on two shelves once — online and rendered from cache.
- [ ] Both header actions render at every width; a successful import refreshes the list in place.
- [ ] The import button does not move when its status message appears, and no blank line is
      reserved for the message while there is none.
- [ ] A book imported from the library header appears in its collection without a reload.
- [ ] Opening a book floats the collections holding it to the top, most specific first; empty
      collections sit last. The order is the same online and rendered from cache.

## Known gaps
- The page renders one section per collection with no cap, and an empty collection still costs
  a heading and an empty-state box. At a few dozen collections the page is unusably long;
  ordering only ensures what matters is at the top. Collapsing empties or capping sections
  needs a design pass.
- Once collection create ships ([[7.3-collections]]), a new collection is empty and therefore
  sorts last — it appears at the bottom of a long page and reads as "nothing happened".
