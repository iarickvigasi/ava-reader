# Library · Private converted-book retention

> Status: proposed deployment defaults; test-only implementation in progress · 2026-09-29.
> Parent: [[_overview]] · Related: [[3.4-import]], [[3.8-pdf-publication]].

## Reader behavior

Removing a book immediately removes the owned Library entry and denies new status, source,
resource and reader access. It fences unfinished conversion and publication. It does not assert
instant physical erasure. The concise confirmation is “Removed from your library.”
Details say private files become eligible for cleanup after the configured grace period
(default 24 hours); backup copies may remain longer. No tested backup-erasure claim exists.

A failed conversion stays Failed. Its original PDF remains owned/downloadable while the entry
exists. There is no reconversion, reader retry or content replacement through cleanup.

## Engineering retention matrix

| Content                                                     | While owned                               | After Library removal          |
| ----------------------------------------------------------- | ----------------------------------------- | ------------------------------ |
| Original PDF / accepted EPUB / canonical reader / resources | Retained                                  | Eligible after 24h grace       |
| Pending review candidate/evidence                           | Retained beyond execution lease           | Eligible after 24h grace       |
| Failed non-source candidate/working files                   | Eligible after 7d                         | Eligible after 24h grace       |
| Unattached staging pins                                     | Existing 1h expiry                        | Same expiry                    |
| Provider prompt/response payload                            | Private operation evidence                | Purged by owned cleanup        |
| Minimal request/failure receipt                             | Owner-scoped replay guard                 | Retained until account removal |
| Minimal billing ledger                                      | Durable accounting; unknown cost retained | Retained, no private payload   |

Grace and failed-work intervals are validated server configuration, not user-facing payment choices.
Sweeps use bounded batches and recheck ownership under the same item lock as removal/publication.
The time means eligibility, not a guaranteed erasure completion time. A failed sweep is observable.

## Invariants

- Cleanup cannot remove live source/final content, pending review or shared/catalog content.
- Purging an operation first preserves its owner/request-key identity and immutable request/source
  hashes in a minimal tombstone. An old upload retry receives a removed result, never a new entry.
- Only explicitly private converted-book lineages with no live Library/catalog references are swept.
  Their source/reader/cover pins must be released before orphan bytes can be reclaimed.
- Account removal may cascade private receipts/content records. Remaining private BookFile pins
  must also be reclaimed; deletion of an operation row alone is not byte erasure.
- Source identities and accepted content are not rewritten to empty placeholders. Minimal retained
  receipts contain no title, extracted text, page image, prompt or response.

## Verification

Exercise actual grace expiry, retained pending review/live Ready, Failed original conservation,
old-key replay after purge, delete/finalize races, account-orphan files, shared source references,
and repeat sweep idempotency in disposable PostgreSQL. Test fault clocks are explicit isolated
configuration. Browser removal and offline cache clearing remain separate required evidence.

Production activation is pending explicit deletion-policy approval after automatic approval review
rejected automatic production scheduling. Helpers reject production mode; no scheduler calls them.
The additive schema/replay protection does not itself purge private content. Current results must
not claim active production cleanup or a physical-erasure service level.
