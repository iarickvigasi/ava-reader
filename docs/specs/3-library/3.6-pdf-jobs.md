# Library · durable PDF conversion jobs

> Status: local boundary; verification incomplete · Updated: 2026-09-29 · Parent: [[_overview]]
> Code: apps/api/src/library/pdf-import/jobs; selected technical decision: [ADR10](../../adr/10-durable-pdf-jobs.md).

## Outcome

An accepted initial PDF conversion survives bounded recoverable process loss without another Library
entry. A stale, stopped, deleted or revoked worker cannot read source bytes, attach output, extend its
lease or change the outcome. Terminal Failed remains Failed and carries a stable safe failure record,
AVA investigation marker and one durable reader-notification intent. Delivery/UI belong to PDF-10.
There is no later conversion, content replacement or reader-facing Retry/Cancel action.

## Behavior

1. Enqueue happens inside the same transaction that accepts the original source and visible item.
   Admission serializes global/per-owner backlog checks; overflow refuses acceptance without a
   partially accepted item. Immutable source/config/profile and a bounded execution policy identify
   the job. Existing accepted queued operations are backfilled; ordinary EPUB processing is unchanged.
2. A separately run operator Node coordinator authenticates a registered, revocable worker principal.
   PostgreSQL claims one due job atomically, advances its attempt fence and issues a fresh opaque
   attempt token. The first claim pins the worker implementation fingerprint; recovery must match it.
   The isolated Python child receives job/source bytes, no database/provider credentials or network.
3. Every heartbeat, source read, output write and completion verifies principal/token, current lease,
   fence, source/config, live item/owner and cancellation epoch. Database time defines lease expiry.
   Stage/progress cannot regress within a generation or exceed the bounded page total. Recovery
   advances generation, resets current progress and preserves prior-attempt progress.
4. Lease expiry or a declared transient native-worker interruption can schedule another attempt only
   before the fixed attempt/time bounds. Recovery restarts deterministic native work from the exact
   original input; reusable page checkpoints remain reconstruction work. Unknown paid outcomes may
   not redispatch. Live provider execution remains closed until PDF-07 supplies spending authority.
5. A completion validates the exact frozen job/result contract and all artifact hashes, sizes, roles
   and aggregate bounds. Owned durable pins precede final result acceptance. Candidate exits 0/2 enter
   WAITING for review and release the lease; they never create Ready or publish content. Review does
   not require a live extraction lease and GC retains its referenced artifacts.
6. Nonrecoverable outcomes or exhausted recovery persist one immutable failure identity bound to
   source/config/stage/attempt, an investigation marker and deduplicated notification intent. Status
   exposes only safe fields. Tokens, local paths, private content and provider payloads stay private.
7. Administrative stop, item deletion and execution revocation advance cancellation authority before
   further work. Late workers refuse; stopping is not a user Cancel control. Existing terminal
   outcomes stay fixed. Accepted artifacts remain private until their explicit retention lifecycle.
8. Development fault controls require an explicit test configuration and cannot run in production.
   Each test records the invoked checkpoint and acknowledgement. Real restart tests wait for short
   test-policy leases against PostgreSQL time; rewriting timestamps is not restart evidence.

## Limits and verification gates

The initial engineering policy is three attempts, a 30-second lease, a 30-minute execution deadline,
two simultaneous jobs globally, one per owner/principal, and 100 global/10 owner queued/running jobs.
These are enforced engineering defaults, not measured capacity promises or reader pricing. Production
changes require a code/configuration release; test overrides require test mode plus the explicit
test-hooks switch and are frozen at enqueue.

- [ ] Concurrent claims and DB-clock recovery pass; separate-process restart still needs its final run.
- [ ] Stale/wrong/revoked credentials and cross-job tokens refuse source/output access and completion.
- [x] Real PostgreSQL retry exhaustion produces one stable Failed/investigation/notification intent.
- [ ] Stop/deletion/revocation source and heartbeat fencing passes; late-completion races remain to verify.
- [x] Real operator execution retains a private review candidate and releases execution authority.
- [x] Isolated resource faults acknowledge their trigger and leave the authenticated API responsive.
- [ ] Backpressure, immutable source/config and existing EPUB regression checks pass.

No publication, provider billing authority, actual notification delivery or complete reader flow is
claimed by this spec. PDF-07/08/09/10/12/13 complete those respective boundaries.

Lease renewal retries only classified transient database failures while the previous confirmed lease
remains live. A failed request never extends it; expiry, invalid authority or operator stop aborts.
Safe worker diagnostics retain the failure code without database text or credentials.
