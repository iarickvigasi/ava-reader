# Library · Validate and publish one finished PDF import

> Status: implemented locally; product reader qualification pending · Updated: 2026-09-29 · Parent: [[_overview]].
> Related: [[3.6-pdf-jobs]], [[3.7-provider-ledger]].

## Behavior

1. Worker completion saves a private candidate and releases its execution lease. A candidate EPUB
   is not Ready. Validation independently checks canonical-v2 semantics, exact resource bytes,
   reconstructed source coverage, chapter/reference corroboration, EPUBCheck and generated-EPUB conservation before publication.
2. Validation records exact source/configuration/candidate hashes and the worker generation/fence.
   Missing content, required links/resources, unknown source qualification, invalid EPUB or reader
   incompatibility is a hard block. An administrator cannot approve away a hard block.
3. AVA reviewers may inspect owned source/candidate evidence and accept explicitly reviewable
   findings. Reader accounts cannot approve. Immutable review provenance names the reviewer,
   policy and finding IDs. This never exposes a draft or a payment prompt to the reader.
4. Publication obtains fresh item/operation authority after validation or review. It refuses deletion,
   cancellation, terminal Failed/Stopped, stale candidates, revoked execution/provider authority,
   unresolved provider charges and an absent or revoked qualified reader build.
5. A single transaction promotes the exact immutable artifacts, stores the accepted manifest,
   creates the finished EPUB/reader files and Ready notification intent, and fixes final content ID.
   Repeating that same publication returns the same identity. Conflicting or later replacement fails.
6. The original PDF and accepted EPUB are formats of the same Library entry. Internal reader JSON
   is not a reader-facing format. Owned resource/download routes authorize the current user/item before lookup and again after
   reading bytes, so a removal during the fetch refuses delivery.
7. Reader delivery selects only the accepted manifest and an independently qualified build/schema. It returns
   the full canonical graph and owned resource URLs; an incompatible client receives an explicit
   unsupported response, never a lossy v2 downgrade. A newly qualified compatible build may read
   existing finished content; the original publication and qualification provenance never change.
8. Validation has a durable lease and fence, at most three attempts and the original import deadline.
   Infrastructure failure permits bounded internal recovery. Invalid content fails permanently.
   Completed immutable validation may await human review beyond the execution deadline; this
   never revives an execution lease or grants another validation attempt. Invalid candidate authority
   is stopped; a waiting candidate cannot monopolize validation of other books.

## Verification boundary

Separate source quality, EPUB conformance, graph conservation, reader rendering and authorization
checks. OCR heading levels must have whole-book source corroboration; a page-local model rank
alone cannot pass the structure check. Missing corroboration produces a source-linked blocking
finding and `not_run`, not a successful consistency claim. Complete ranked outline evidence may
satisfy the check; targeted source refinement remains separate implementation work. Test qualification records cannot enable product publication. Real build qualification needs
independent browser evidence and the compiled adapter/reader fingerprints. Translation capability
is separate; original reading must not invoke the legacy structure-losing translation route.

Exercise validation refusal, review permissions, post-lease retention, stop/delete/approval races,
concurrent first publication, exact replay, owned resources and Ready delivery. No code-presence or
synthetic capability fixture alone is evidence that a user's converted book is readable.

Local evidence: 17 actual coordinator/publication checks and 29 extended PostgreSQL checks passed
at the recorded snapshots, including real isolated EPUBCheck. Nineteen focused checks cover source
requirements, scheduling fairness and lost authority. Later source changes need affected reruns.
