## Summary
The per-book detail page: description, reading stats, collections, and the read / save-offline
actions.

## Behaviour
1. Shows cover, title, authors, description, genres, language, published year, approximate page
   counts, minutes read, completion percent, chapter label, and the book's collections
   ([[3.5-library-payloads]]).
2. The cover links to the reader — identical to the Read button, including the offline
   missing-book interception when the book isn't saved. While navigation is pending the Read
   button swaps its label to "Opening" + trailing ellipsis dots ([styles.md](../../styles.md)
   §Buttons); the cover shows no pending state.
3. Save-offline toggles LibraryItem.offlineRequested ([[4.2-save-sync]],
   [[4.3-save-button]]).
4. Add to collections counts custom memberships and opens the existing dialog with all CUSTOM lists,
   including empty ones. SMART collections are omitted entirely. Current memberships start checked;
   clicking a row or its checkbox toggles the draft. Save changes commits additions and removals;
   Cancel, Escape, and backdrop dismissal discard the draft. Focus returns to the action card.
5. The picker reuses theme surfaces, serif titles, checkmarks, and shared modal buttons. Long lists
   scroll while the footer stays visible. Checked rows share the same fill and checkmark; the inset
   focus ring appears only for keyboard navigation. Save is disabled until the draft changes.
6. With no custom collections, show “No collections yet” and “Create a collection in your library,
   then come back to add this book.” Offer Go to library and Close. A missing offline collection
   cache is an unavailable state, not an empty library. Loading failures offer retry.
7. Below a divider, show Highlights and AI Comments with total counts, newest first. Desktop uses
   two equal columns with every item in the page flow. Below `lg`, stack highlights before comments;
   each list scrolls independently with a maximum height of `100dvh`, without an item cap or Show all.
8. Highlights show plain passage text. AI comments show the source and full response with no expand
   control, using the same row typography and spacing. Neither list offers recoloring or text edits.
   Both reuse the reader's touch-visible overflow trigger and Delete action. Menus float beside the
   trigger without shifting rows, escape scroll clipping, and flip above near the viewport bottom.
   Outside interaction or scrolling dismisses them; Escape closes and restores trigger focus.
9. Cached chapter names appear when available. Annotation loading, empty and failed states are
   independent; cached items remain visible while refreshing. Queued/failed AI responses show status.
10. Each annotation heading has an always-visible three-dot button opening a Copy all menu. Copy
    includes every current item in that section, including items outside its scroll viewport, in
    displayed order. Plain text preserves paragraphs and separates entries clearly. Highlights
    include the passage and cached chapter name; comments include the source, kind, cached chapter,
    full available response and any displayed pending, failed or empty-response status.
11. Copy all is disabled for an empty list. Cached lists remain copyable offline and during refresh
    failures. Copy reads the current list without fetching. When the clipboard write finishes, close
    the menu and return focus to its trigger. Show the existing bottom-of-screen app toast:
    “Highlights copied” / “AI comments copied”, or “Couldn’t copy. Please try again.” on failure.
    Labels and feedback are localized; menus support keyboard and touch like the row menus.

## Data & sync
Book-info details lazy-loaded once and cached; GET /library/:ref. Book-info + collection pages
are generic client shells ([[4-route-precaching-service-worker]]) hydrated from Dexie by
`location` slug.
Membership edits use the library bucket: update locally, persist, and sync on reconnect. Selection
comes from complete book memberships plus pending changes, never the four-book collection previews.
The book's collection count updates reactively; sync failures are surfaced without losing unrelated
changes. See [[3.3-collections]] for the membership write contract.
Annotations subscribe to the same per-book highlights and AI-comments buckets as the reader.
Deletes update immediately, persist offline and sync on reconnect; no new API payload is required.

## Acceptance criteria
- [ ] Book-info shows progress and offers read + save-offline actions; the cover opens the
  reader.
- [ ] The Read button shows "Opening" + trailing dots while reader navigation is pending.
- [ ] Renders offline from cache.
- [ ] Picker shows only custom collections and accurately preselects existing memberships.
- [ ] Save adds/removes memberships; cancellation changes nothing; empty-state copy is localized.
- [ ] Saved edits survive offline reload and sync on reconnect; keyboard and mobile layouts work.
- [ ] Each header menu copies its complete list in order, preserving text and comment statuses.
- [ ] Empty lists disable Copy all; cached lists copy offline; completion closes the menu with toast
  feedback and restores trigger focus.

## Known gap / planned fix
- Picker options can prefer an older in-memory library over newly read cached collections. Use one
  cache-backed options source; remove the competing library snapshot. Preserve loading, retry, and
  the distinction between an unavailable cache and a confirmed empty collection list.
- Verify opening offline after a collection is created, renamed, or deleted in another tab; changes
  read from the cache must appear in the picker. Membership drafts remain separate from option data.
