# Library · AVA-funded provider authority

> Status: implementation target · Updated: 2026-09-29 · Parent: [[_overview]]
> Code: apps/api/src/library/pdf-import/providers · Related: [[3.6-pdf-jobs]].

## Behavior

1. AVA funds processing. Readers never supply keys, approve charges or see balances. Native work has
   no provider dispatch. Initial import pins an operator-configured route grant; later recognition
   tasks cannot change its model/provider/prompt/schema allowance or add a broader fallback.
2. Before dispatch, the server verifies current worker/attempt/item authority, the immutable grant,
   source/configuration, exact request identity and a current verified tariff. It atomically reserves
   the conservative maximum against global, account, exact-model and operation caps. Integer USD
   nanodollars avoid floating accounting; historical model spending remains in the same cap.
3. The provider call ID and exact bounded request bytes are durable before network I/O. One task ID
   identifies the same request across recovery generations. A settled response can be reused; a
   changed request cannot reuse the ID or obtain a new route grant to bypass the accepted policy.
4. Dispatch intent is committed before sending. A sending crash, timeout or missing cost receipt
   preserves its reservation as uncertain and pauses the affected route. It is never silently
   resent. Reconciliation needs authoritative evidence; terminal Failed cannot reopen through it.
5. Settlement replaces reserved exposure with actual cost exactly once. Late receipts remain
   attributable after stop/failure; private content remains owned and is removed with account
   cleanup, while minimal accounting history persists. An unexpected provider overcharge is
   recorded truthfully, stops the route and is never hidden by clamping the receipt.
6. Provider credentials remain in the trusted host process. The isolated recognizer supplies bounded
   image/text tasks and consumes recorded responses. It receives no network, key or ledger access.
7. Approved routing disables fallback, plugins and automatic retries, requires supported parameters,
   and pins maximum prices/data policy. Missing rates, unsupported billing components or absent
   authorization fail closed before dispatch. Reader status remains safe and money-free.
8. A route explicitly pins a request timeout of at most 300 seconds. Longer request allowance does not
   extend the original job deadline or lease; authority loss aborts earlier. Existing routes retain
   their configured timeout. A timeout still means uncertain billing, never an automatic retry.

9. Gemini recognition uses a compact generation grammar with inline references and the flat v2
   observation shape. Conditional kind rules and unsupported size/pattern constraints remain in
   the unchanged host JSON Schema and Python semantic validator. This grammar guides generation;
   it is not equivalent acceptance validation. Exact encoded request hashes bind the transformation.
   Invalid responses are refused without repair, coercion or automatic resend.

## Finite pilot boundary

Live routes require a finite inventory bound to privately saved operation and owner IDs, exact source
hashes, worker image, task/render hashes and final encoded request hashes. Missing IDs are not usable
route configuration. Every listed task has one retained call identity; a successful receipt may be
reused, but a released, failed or uncertain request never gets an additional send. Unlisted work
refuses rather than broadening the inventory. Stub/replay fixtures can exercise the same guard.

The pilot pins per-operation reserves to its task count, totals at most $1, and requires global and
account hard caps at most $1 plus the existing cumulative exact-model cap at most $10. Existing
accounting is never reset. These checks do not enable live enqueue or worker claims, create routes,
authorize document transmission or assert live quality. Ordinary live import remains disabled; the
operator-only synthetic pilot uses a separately scoped disposable database boundary.

## Verification

Concurrent caps, exact identity, intent/receipt crash recovery, stopped/deleted authority and owned
payload cleanup require actual disposable-DB and authoritative stub-counter tests. Live calls need
reconciled remaining authorization and current verified rates. Injected tests are not live billing
proof. One authored-fixture request settled at $0.00137265 before immutable INVALID_RESULT failure.
The response exposed schema/semantic, geometry and structural gaps; version2 repairs pass offline
checks, but provider grammar support and whole scanned-book fidelity remain unqualified.
