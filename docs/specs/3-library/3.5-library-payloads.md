# Library · payloads (server)

> Status: shipped · Updated: 2026-09-13 · Parent: [[_overview]] · Code: apps/api/src/library

## Summary

The server reads behind the library UI: the two-phase overview, collection and book-info reads,
and the public cover endpoint. Every book list serializes the shared card shape ([[_overview]]).

## Behaviour

1. GET /library returns `books`: every active owned book card, engagement-sorted, independently
   of collections. Collection summaries contain every owned collection, four-card previews,
   complete completionItems membership/status snapshots, and active item/unread totals.
   `summary.booksCount` counts active LibraryItems directly; collectionsCount counts owned collection
   rows. All collections are user-created after migration.
   `libraryItemIds` contains all owned identities, including archived items, for safe cache pruning.
   Reads share a repeatable-read transaction. Cover bytes are never selected; cards carry URLs.
   Clients derive the general books grid from the complete catalog minus custom memberships,
   overlaid with pending edits. Cache active catalog IDs separately from all owned identities so
   archived metadata cannot reappear as uncollected books. Older payloads may omit books.
2. GET /library/collections/:ref (id or slug) — the full collection with all active books,
   engagement-sorted, in the same summary shape as the overview sections.
3. GET /library/:ref (id or slug) — the book-info payload: metadata, approximate page counts,
   progress fields, the item's collections (sorted sortOrder then name), primaryFormat, and the
   user's explicit finishedAt timestamp (ISO string or null), independent of progress.
4. PATCH /library/:libraryItemId/offline — sets offlineRequested only ([[4.2-save-sync]]).
5. GET /library/covers/:bookId — public, unauthenticated, long-lived Cache-Control: covers are
   not sensitive, ids are unpredictable CUIDs, and `<img>` tags skip Clerk token juggling. Cover
   bytes are never inlined in payloads — cards carry this URL instead.
6. primaryFormat is the primary SOURCE file's format (a processed book also carries a primary
   DERIVED_READER file — kind disambiguates). Archived items are excluded everywhere.
7. Addressing: a slug is accepted only where the browser URL is the client's sole identifier on a
   cold load — reads 2 and 3 above, plus GET /library/:ref/reader ([[2.7-reader-payload]]). Both
   also take an id, so pre-slug `/app/read/<id>` links still resolve. Every other library-item
   endpoint is id-only (offline, reader progress/sessions, annotations, ai-comments): each is
   downstream of a payload that already carried the id, so accepting a slug would widen the
   lookup for no caller. The id-only checks skip the archived filter — nothing archives yet.
8. PATCH /library/:libraryItemId/finished — authenticated, id-only, owner-scoped and excluding
   archived items. Body: `{ finishedAt: <ISO timestamp with time zone> | null }`; missing or invalid
   values return 400. Returns `{ libraryItemId, finishedAt }` with a canonical UTC timestamp or
   null. Sets only LibraryItem.finishedAt; repeated identical values are idempotent. Existing
   rows default to null, with no backfill from percentage or reading activity.

9. DELETE /library/:libraryItemId — authenticated and owner-scoped. Removes this user's library
   copy and its dependent progress, annotations, translations, and memberships. Shared Book/source
   records remain. An ownership receipt makes retries idempotent and authorizes later completed
   offline session replays. Unknown or foreign IDs return 404. Reading sessions, participants, and
   segments retain their historical item IDs without a cascading library-item foreign key;
   user deletion still cascades them. Reading-hour totals continue summing all the user's segments.

## Edge cases

Unknown ref or another user's item/collection → 404; missing cover → null coverImageUrl and 404
from the cover endpoint; empty library → empty collections and zero counts.
