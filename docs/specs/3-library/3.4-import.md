## Summary

Server ingest: POST /library/import turns an uploaded EPUB/PDF into a Book with stored files and
a LibraryItem on the user's shelf. Adding from the catalog reuses the same add-to-library core.
Optional PDF-to-EPUB conversion is a separately qualified candidate: conversion is selected during
import, and its durable library entry shows processing or failure until a validated book is ready.
Source-only PDF import remains available when conversion is not selected.

## Behaviour

1. Only EPUB and PDF are accepted (server-side format detection); anything else 400s.
2. Metadata (title, authors, description, genres, language, published year, cover image) is
   extracted server-side; the source file and cover are stored as blobs. EPUB subjects split on
   commas and spaced hyphens/double hyphens; genres are trimmed, nonempty, and deduplicated in order.
   Subjects beginning with a numbered list (`1. Topic. 2. Topic.`) also split at number markers
   and drop each item's final period; ordinary subjects retain periods and abbreviations.
   A one-time deployment migration applies these rules to stored genres on all existing books,
   including private imports and catalog books, without changing ownership or reading data.
3. Blob bytes are written before the metadata transaction — multi-MB writes would blow the
   interactive-transaction timeout and hold row locks for the whole upload. If the transaction
   fails, the blobs are best-effort deleted; leftovers are swept by the orphan-blob GC.
4. An ordinary EPUB enqueues a normalize-reader-package-v1 processing run
   ([[2-reader/2.7-reader-payload]]). A PDF stores the source only when conversion is not selected.
   With conversion selected, the entry keeps its original PDF and background import operation;
   the finished EPUB becomes available only after content validation and accepted publication.
   Conversion happens once during PDF import. Finished content stays fixed: there is no later
   reconversion or content replacement. Existing tagged canonical EPUB imports retain their
   canonical authority rather than using ordinary EPUB regrouping.
5. Add-to-library is idempotent per user+book: an existing item returns state "existing" (and
   backfills originCatalogEntryId when newly known); otherwise the item is created with a unique
   per-user slug built from title+authors, a zeroed ReadingProgress, and smart-shelf membership
   ([[3.3-collections]]). Ordinary imports and catalog adds return LibraryMutationPayload
   {state: added | existing, book, slug}; converted PDF import returns its durable operation.
6. Catalog adds flow through the same core with source CATALOG and the originating catalog entry
   recorded; only PUBLISHED entries can be added.
7. Client side, a successful upload revalidates the library bucket and refreshes the router, and
   the status message it shows must not displace the import button ([[3.1-library-screen]]).

## EPUB chapter labels

Combine consecutive opening headings with a spaced slash (`number / title`), retaining authored
chapter numbers and words. Combine at most three distinct headings and 240 characters total;
if either limit is exceeded, keep the first heading alone. This prevents pages whose prose is
mis-tagged as headings from becoming a single oversized name. Apply the same eligibility rule
to offline partial-name refresh.
Short centered paragraphs with a font-size scale of at least 1.125 count as heading candidates.
A short centered Chapter/Part number or Preface also starts a centered heading group without
a font-size hint. Heading-only pages may use the book title as their name. Partial combined
labels can gain further opening subtitles.
Skip images and empty blocks; stop at prose or blockquotes, never promote later subsection headings.
Numeric NCX labels remain text, including zero; use explicit opening headings to enrich numeric
labels. Repair legacy TOC filenames that match their own target href from canonical chapter names.
Preserve complete TOC names; enrich names matching one component of the opening heading group.
Short unstyled paragraph guesses retain the existing book-wide coverage safeguard.
Otherwise use chapter order plus up to six words of the first body sentence and `…`.
During EPUB import, merge each run of picture-only logical chapters into the following text
chapter, keeping pictures first and in order. Image alt text is not prose. Retain trailing
picture-only chapters when there is no following text. Discard empty/whitespace-only content.
Keep all surviving chapter IDs and block IDs; use the destination chapter's title. Rebuild
sequence indices, neighbours, counts, and fallback contents; authored TOC targets retain their
original block destinations inside the merged chapter. This applies to new packages only;
existing packages require an explicit maintenance migration and client cache refresh.
Resolve references against their original source document before grouping. Afterwards, internal
links and note returns keep the same block and text position in their new owning chapter; missing
or ambiguous destinations fail import instead of being guessed.
Contents and reader header use the same canonical name. Existing package repair upgrades exact
generated labels and partial opening
names; matching TOC entries and progress-index labels follow. Offline refresh fetches canonical
server names for these candidates without downloading content again.

## Edge cases

Each intentional ordinary EPUB/source-only PDF upload creates a new Book and LibraryItem, including
a repeat upload of the same file. Converted PDF requests replaying the same owned idempotency key,
source and options reuse the same operation and library entry; a new intentional import uses a new
key. Adding the same catalog Book again returns "existing".
Rejected uploads before durable admission create no visible book; unsupported file → 400 before
any write. Once a converted PDF operation is admitted, failure keeps its library entry with Failed
status and diagnostic evidence for investigation. No partial candidate becomes readable. Unowned
or unreferenced temporary blobs follow the existing artifact cleanup and GC lifecycle.

## Acceptance criteria

- [ ] Importing an EPUB or PDF creates the book, its smart-shelf membership, and progress at 0.
- [ ] An intentional new ordinary EPUB/source-only PDF upload creates another Book and LibraryItem.
- [ ] Replaying an admitted converted PDF request with the same owned key/source/options creates
      no duplicate operation or library entry.
- [ ] Converted PDF status appears in its library entry; failure stays visible as Failed and the
      finished readable EPUB is offered only after validation and accepted publication.
- [ ] A finished converted book retains one fixed content identity alongside its original PDF;
      no later reconversion or replacement alters its content or stored reading positions.
- [ ] Adding the same catalog Book again returns state "existing" and adds nothing.
- [ ] Untitled chapters use six-word opening excerpts with order numbers and a trailing `…`.
- [ ] Picture-only runs merge forward with block order/IDs and TOC targets preserved; trailing
      pictures remain readable and empty documents are omitted.
- [ ] Grouping preserves internal links and note returns, including nested list/table and image
      destinations, across source directories and exact UTF-16 offsets.
- [ ] Sparse TOCs and untitled front matter never suppress an explicit opening chapter heading.
- [ ] Separate headings `1` and `Wanted: Men Who Love` yield `1 / Wanted: Men Who Love`.
- [ ] Label repair preserves blocks, IDs, locators, nested authored TOC labels, and progress counts.

## Opening/ending grouping (imports and maintenance backfill)

- Maintenance backfill applies only to mutable legacy EPUB readers. Finished PDF conversions and
  canonical/generated EPUB imports retain their accepted content and are excluded from the scan,
  processor and atomic swap, independently of whether user marks currently exist.
- New ordinary EPUB imports and mutable existing packages combine consecutive, positively identified
  opening pages (cover, title, copyright, dedication, epigraph, also-by) into **Front matter**.
  Image-only opening pages may join that positively identified run. Contents and named About the
  Author stay separate.
- Stop opening-page grouping at the first unclassified or substantive section. Never infer front
  matter from brevity alone; preserve introductions, prefaces, and prologues.
- An Appendix followed by consecutive picture-only documents absorbs those images, preserving
  its name and stopping before the next text document. Imports and backfill share this rule.
- At the end, combine consecutive semantic footnote documents into **Footnotes**, preserving
  separate Notes, Bibliography, Index, acknowledgments, author biography, and promotional sections.
- During backfill, preserve every block byte-for-byte and in order, all block IDs, and surviving
  chapter IDs.
  Only grouped chapters, navigation neighbours, sequence indices, contents, and counts change.
  Middle chapters (including heading-only middle segments) are outside this backfill's scope.
- Preview by default. Application requires maintenance and skips books with offline intent,
  references to removed chapters, running processing, or incompatible progress counting flags.
  Source internal targets to removed chapters also block regrouping; preserve their source bytes
  and links until an explicit reference migration is available.
  Keep the old package/index as a rollback file. Existing client content caches need refreshing;
  this is a server maintenance tool, not an automatic offline cache migration.
