# Reader · content rendering

> Status: shipped · Updated: 2026-08-10 · Parent: [[_overview]] · Code:
> apps/web/components/app/reader/content, apps/web/features/reader/break-opportunities.ts

## Summary
Turns a chapter's structured blocks into styled, readable DOM — the visible page content.

## Scope
- In: rendering ReaderBlock types (paragraph, heading, list, image, …), ReaderInline runs (text |
  image), list items, block alignment, reader typography, applying font scale and theme to the
  content, keeping every line inside its column.
- Non-goals: how content is split into pages (see pagination), where it scrolls to (see
  navigation/resume), selection handling (see selection-bridge).

## Behaviour
1. reader-article renders the active chapter's blocks in order; reader-block-view styles each block
   by type and align (left|center|right|justify).
2. Inlines render as text or inline images; images resolve from cached blobs.
3. Font scale and theme (data-theme + CSS vars) apply live without re-fetching content.
4. Each block carries its stable blockId so locators and marks can target it.
5. No line may exceed its column. A column is a page (see pagination), and an over-wide line is not
   wrapped or clipped by multicol — it paints across the gap into the next column, so its head is
   clipped at the page edge and its tail lands on top of the next page's text. Two layers prevent
   it: `break-words` on the article (inherited, so it also covers marks and future block kinds) is
   the guarantee, and `<wbr>` opportunities injected into long tokens choose *where* the break
   lands. Both live in shared render code, so the offscreen measurement article gets identical
   geometry.
6. splitAtBreakOpportunities picks those points: tokens from MIN_BREAKABLE_TOKEN_LENGTH characters
   up, after a run of URL punctuation (so `https://` stays whole), never between two digits (so
   `1,234.56` stays whole). `<wbr>` adds no characters, so locator textOffsets — counted over text
   data by range-marks and compute-ai-comment-locator — are unchanged. `&shy;`/zero-width spaces
   would drift every saved locator; `hyphens: auto` would hyphenate by UI locale, since `<html
   lang>` is the UI locale and ReaderBookPayload carries no book language.

## Data & sync
Input: ReaderChapterPayload.blocks (api-types/reader.ts). Read-only; no mutations. Reader serif
typography via CSS font vars.

## Edge cases
Unknown/empty block type → skip gracefully; missing image blob (offline) → placeholder; very long
block; mixed-direction text; extreme font scale. A token with no break opportunity (bare URL, long
compound word, any word at heading size) at MAX_FONT_SCALE, where a mobile column holds ~24
characters. A highlight spanning an injected break becomes several `<mark>`s — already the norm for
a range crossing inline runs, and roundHighlightEnds shapes only the outer ends.

## Acceptance criteria
- [ ] Each block type renders with correct structure and alignment.
- [ ] Font scale and theme changes restyle content instantly, no refetch.
- [ ] Every rendered block exposes its blockId for anchoring.
- [ ] No glyph paints outside its column: paging through a chapter of bare URLs at min and max font
      scale never shows a clipped line at the page edge or a stray fragment over the next page.
- [ ] A long URL breaks after a slash or hyphen, not mid-word; ordinary prose and numbers keep
      their default breaks.
- [ ] Selecting across an injected break yields the same text as before, and a highlight over one
      paints as a single continuous wash.
