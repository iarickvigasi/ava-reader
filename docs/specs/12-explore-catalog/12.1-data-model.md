# Explore · canonical data model

> Status: draft · Updated: 2026-10-23 · Parent: [\_overview](_overview.md)

Implemented subset: [foundation](12.5-foundation.md). The full model below remains the target.

## Entities in catalog PostgreSQL

All canonical IDs are immutable AVA-generated UUIDs; provider IDs are mappings, never primary keys.
Queryable relationships/constraints use typed columns; irregular source payloads use JSONB or raw
object-storage records. Include createdAt, updatedAt, and a monotonic revision on mutable entities.

| Entity                         | Principal fields and constraints                                                     |
| ------------------------------ | ------------------------------------------------------------------------------------ |
| Work                           | id, originalTitle, originalLanguage, firstPublication date with precision, status    |
| WorkText                       | workId, locale, title, subtitle, description; unique (workId, locale)                |
| Edition                        | id, workId FK, title, language, publisher, publication date/precision, format, pages |
| Author                         | id, displayName, birth/death date with precision, entityKind (person/organization)   |
| AuthorText                     | authorId, locale, biography; unique (authorId, locale)                               |
| AuthorAlias                    | authorId, name, language/script, normalizedName; names are not globally unique       |
| WorkCredit                     | workId, authorId, role, creditedAs, position; unique (workId, authorId, role)        |
| EditionCredit                  | editionId, authorId, role, creditedAs, position; translators/editors/illustrators    |
| Subject / WorkSubject          | canonical vocabulary and many-to-many work links; preserve source terms              |
| Identifier / EditionIdentifier | scheme, normalizedValue; many-to-many assertions with provenance                     |
| WorkRelation                   | fromWorkId, toWorkId, relation (adaptation/contains/related); optional enrichment    |
| ExternalRecord                 | sourceId, entityKind, externalId, sourceRevision, target ID; unique source key       |
| Source / IngestRun             | provider policy, adapter version, dump/job identity, status, checkpoint              |
| FieldAssertion                 | target, fieldPath/locale, value, sourceRecordId, observedAt, confidence, state       |
| CatalogAsset                   | editionId, kind, URL/objectKey, checksum, rightsState, territories, evidence         |
| EntityRedirect                 | entityKind, oldId, canonicalId; unique oldId; retained after merges                  |
| CatalogOutbox                  | sequence, entity/revision, eventType, payload, createdAt; durable consumer cursors   |

ExternalRecord and assertions must reference a real Work, Edition, Author, or Asset using typed
nullable FKs with exactly-one-target checks, rather than unconstrained polymorphic strings.
EditionIdentifier is unique per (editionId, identifierId); identifier matches may be ambiguous.
Descriptions/covers/biographies need provenance independently of simple bibliographic facts.

## Identity rules

- Work is the intellectual book; Edition is a publication/translation/format. A translation keeps
  the work link but has its own language and translator credits. Anthologies can link constituent
  works without flattening their authors. Model an expression layer later if demonstrated need.
- ISBN belongs to editions, not works. Validate checksums, normalize ISBN-10 to equivalent ISBN-13,
  preserve original assertions; erroneous/reused identifiers must not force a global unique edition.
- Names and title+author are candidate signals, never unique keys. Preserve Cyrillic/Latin names,
  diacritics, localized titles, pen names, and historical publication-date uncertainty.
- Auto-link trusted provider relationships; cross-source merges require identifier/context agreement.
  Ambiguous cases remain separate/reviewable. Record merge evidence and support correction/splitting.
- A merge retains old IDs as direct redirects; prohibit cycles and flatten chains transactionally.
  Reassignment/split corrections are audited; they do not silently rewrite user content links.

## Indexes and projections

B-tree: Edition(workId, id), credits(authorId, workId), Edition(language, workId), source keys,
identifier(scheme, normalizedValue), redirects, outbox(sequence), and partial pending job indexes.
WorkSearch holds one compact public projection per work with localized titles, author aliases,
language/subject facets, cover reference, and revision. AuthorSearch is separate. Index weighted
tsvector with GIN and normalized short titles/names with pg_trgm; maintain projections via outbox.
Exact identifier lookup joins editions to works through B-tree indexes, ahead of fuzzy search.
Use per-language configurations where available and a simple-token fallback; do not stem all
languages as English. Benchmark short names, non-Latin scripts, and mixed-language queries.
