# Explore · import order and later linking

> Status: active · Updated: 2026-10-29 · Parent: [\_overview](_overview.md)

## Terms and relationships

- A **work** is the literary creation: for example, Pride and Prejudice.
- An **edition** is one publication/translation, with its language, publisher, year, and
  identifiers. Many editions can describe the same work; each edition belongs to exactly one work.
- A **reading copy** is an actual EPUB and its processed reader data, with a permanent file
  identity. An edition may have several reading copies. A metadata description alone is not a
  readable book.
- A **private upload** belongs to its user. Linking it to a public description never publishes its
  file or reveals its existence to anyone else.

“Attach an edition to a work” and “attach a work to an edition” change the same edition.workId
relationship. The two screens must call the same operation and enforce the same rules. Private-copy
links are separate, user-owned relationships in Main, not files copied into Catalog.

## What works today

The metadata importer creates work/edition relationships from exact Open Library IDs. Editions can
arrive before their work description: a placeholder keeps the work ID until the real record arrives.
Ordinary Open Library inventory requires completed metadata runs, edition mappings, and retained
source records. Curated bootstrap is a separate path; removing the ordinary validation is unsafe. An
EPUB must match an exact edition; title/author similarity is only a suggestion, never an identity.
The extension below adds explicit edition reassignment and private-copy links; metadata-only shelves
and cross-source merges in [12.2](12.2-personal-library.md) remain separate future work.

## Release classics before the full metadata collection

Two approaches are possible; neither needs to download the full metadata collection first.

1. **Small metadata subset first, using the current importer.** Supply genuine Open Library author,
   work, and edition records for the chosen classics, including each edition's IA file references.
   Finish these small import runs, then inventory, inspect, upload/process, review, and publish
   EPUBs. Import the full dumps later. Existing source mappings keep the same AVA IDs; repeated
   provider records update/skip existing descriptions rather than creating another copy of the same
   source ID. This is a supported sequence, not a new subset-extraction/download command. Exact
   records still need to be supplied. A currently unfinished bulk run still blocks the EPUB CLI and
   uses the lock only while reading/writing Catalog metadata.
2. **EPUBs first, without Open Library records.** Use the implemented curated ingestion mode. An
   admin supplies the file, title, author, language, and exact source/rights evidence. Create stable
   local work/edition IDs, then reuse Catalog storage, processing, review, and publication. Import
   Open Library later and explicitly attach verified provider mappings to these existing
   descriptions. CLI --bootstrap accepts a bounded list of shortlist titles with exact IA
   identifiers and optional filenames. It writes local descriptions/source records, then emits the
   normal inspection manifest. Candidate validation and publication accept only registered Open
   Library or curated-classics provenance. Curated manifests bypass the completed-Open-Library check
   but retain locking around Catalog mutations.

Prefer the small subset when exact Open Library records are available. Use curated ingestion when
the EPUB source is independent or Open Library lacks the edition. No bulk API harvesting is needed.

## Linking from either side

1. Admins may select a work from an edition or select editions from a work. One Catalog operation
   checks both records and their revisions, records the correction, and changes only the
   relationship. Reject deleted targets and conflicting edits; do not silently overwrite another
   admin's correction.
2. Keep edition, file, checksum, main reading-entry, and LibraryItem IDs stable. A corrected work
   link updates review lookup/deletion routing, candidate validation, and pending publication
   receipts. This is public administration only: it never reads or updates private-copy links.
   Main's public import manifest embeds workId, so its public references need repair too.
3. Later provider matching needs explicit IDs/evidence and operator confirmation for ambiguous
   cases. Bind provider records to existing local IDs before applying the corresponding full-dump
   rows. Already-imported duplicates need a separate reviewed merge/redirect operation; changing a
   source mapping alone is insufficient. Preserve provenance and admin edits. Never merge by title
   alone.
4. Users may choose a catalog work from their private upload, or choose their own
   upload from a catalog page. Both use one ownership-checked Main mutation and the library bucket's
   offline queue. Private links refer to works only; exact-edition selection is omitted.
   Only the owner may read/change this link, including when another account is an admin. Private
   uploads never become public Catalog editions. In Library, place Link to catalog in the book-info action column and its button description
   reads “Link is visible to you only”. Localize its labels in all supported UI locales; use the
   Explore compass icon with the same stroke weight as adjacent actions. Action descriptions use
   regular-weight UI type consistently. Explore labels private uploads “Visible to you only”.
   Public corrections never rewrite the owner’s saved choice; only the owner can relink it.
5. Relink/unlink description references only. Preserve bytes, reading positions, annotations,
   personal collections, and file access. Cache the last accepted description for offline reading
   and outages. Do not send private files, hashes, user IDs, or shelf membership to the public
   Catalog API. The initial implementation stores one optional link/snapshot per LibraryItem,
   separate from shelf memberships. Pending link/unlink intents coalesce per copy, persist across
   restarts, and retry on reconnect. Permanent validation/ownership failures restore the accepted
   link and display an error. Version fences prevent a delayed mutation overwriting a newer link,
   including across devices. Work reassignment repairs Main references after Catalog commits; failed
   repair requires explicit retry.

## Verification

Test both import orders without duplicate IDs or file processing; edition reassignment with pending
publication; stale/conflicting provider matches; offline private link/relink/unlink from either
screen; other-user access denial; and unchanged files, progress, highlights, and collections after
each link.

Commands and collection/binding formats: [EPUB-first operations](../../catalog-bootstrap.md).

## Curated digital EPUB sources

Bootstrap accepts explicit `provider` (`standard-ebooks` or `wolne-lektury`) and `providerId`
(Standard Ebooks author/title slug or Wolne Lektury book slug), as alternatives to an IA identifier.
Provider identity, canonical source URL, metadata snapshots and exact EPUB hash remain attached to
the edition. The same title/author/language reuses the curated work, while each source has its own
edition; changing file bytes never replaces an acquired reading identity. Network redirects stay
on that provider's allowlisted HTTPS hosts. Downloads are bounded and updates require inspection
again. Source notices remain in the EPUB/reader. Collection copies publish with review deferred.

## Edition source and rights research

After staging a verified EPUB, the importer records public Catalog evidence keyed by edition and
SHA-256: provider, source/download URL, filename, inspection date and matching shortlist research.
Replays upsert the same evidence; another file hash retains a separate record. Edition details show
source and download links for everyone. Work headers and public reading controls show no review-status
or rights-evidence links. Inspection dates, rights status and research are admin-only,
loaded through the authenticated editorial endpoint and omitted from public evidence responses. Original-work term screening
is explicitly distinct from exact-file rights/quality approval and never publishes a draft.
Only READY assets with the same checksum supply approved distribution scope/basis. Missing research
is shown as unavailable, never inferred from a provider or title alone. No private-upload evidence.

Source discovery records title/author matches, actual formats and reuse evidence separately.
A PDF scan, partial volume, metadata record or unverified export is never labelled a ready EPUB.
Search failures and remaining gaps stay explicit; source discovery does not change publication state.
