# Explore · catalog foundation

> Status: shipped · Updated: 2026-10-23 · Parent: [\_overview](_overview.md)
> ADR: [10](../../adr/10-independent-book-catalog.md) · Code: apps/catalog

## Scope

Independent read-only metadata API and catalog DB, with no dependency on the main API/DB.
Public records currently have no draft/publication workflow; only approved public metadata belongs
in this DB. Open Library ingestion/outbox follow in [12.6](12.6-open-library-import.md); search, source policy
automation/field assertions, assets, personal linking, and UI remain future milestones. Local fictional fixtures establish relationships without importing feeds.

## Data and behavior

- Work/WorkText, Edition, Author/AuthorText/Alias, work/edition credits, normalized identifiers,
  edition-identifier links, Source, and typed SourceMapping are the first schema subset.
- UUID IDs belong to AVA. SourceMapping uses foreign keys and an exactly-one-target SQL CHECK
  matching entityKind (WORK/EDITION/AUTHOR). Source IDs are unique within provider and kind.
- Edition identifiers may match several editions; descriptions and author text can be localized.
  Publication year is optional; precise dates, revision automation, and merge tools are deferred.
- GET /api/health checks the catalog DB; returns 503 when unavailable.
- GET /api/works/:id returns work metadata, localized texts, and ordered author credits.
- GET /api/works/:id/editions returns editions, contributor credits, and identifiers.
- GET /api/authors/:id returns author metadata, aliases, and localized biographies.
- GET /api/authors/:id/works returns distinct works credited at work level.
- Lists return { items, nextCursor }, 20 items maximum, ordered by UUID; cursor is the exclusive
  lower bound. Edition-only contributors remain visible on edition credits, not work authorship.
- Malformed UUIDs/cursors return 400, missing detail/list-parent records return 404. Lists for
  existing parents with no children return an empty items array and null nextCursor.
- No public writes, private content, user state, or main database joins are exposed.
- Optional demo seed runs explicitly, is transactional/idempotent, and never runs on service startup.

## Acceptance criteria

- [x] Fresh migration and repeat seed produce linked works/editions/authors in catalog alone.
- [x] Detail and paginated relationship endpoints return bounded metadata and correct 400/404s.
- [x] Invalid/multiple source targets and duplicate provider keys are rejected by PostgreSQL.
- [x] Main and catalog Prisma clients generate independently without sharing schema/client output.
- [x] Catalog starts without requiring main API/DB; endpoints use only the catalog database.
