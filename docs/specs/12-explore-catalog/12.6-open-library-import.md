# Explore · Open Library metadata importer

> Status: shipped · Updated: 2026-10-27 · Parent: [\_overview](_overview.md)
> Code: apps/catalog/src/importer, apps/catalog/src/importer/main.ts

## Scope

Explicit local-file CLI imports of Open Library author/work/edition TSV dumps, plain or gzip.
No network crawling, API harvesting, file downloads, source redirects/deletes, multi-source merges,
curator UI, or search consumer. Retain full source JSON for provenance, not as a public API payload.
This is a resumable first adapter, not a benchmarked full-corpus bulk loader.

## Contract

- Hash original file bytes before import. Run identity is SHA-256 plus adapter version. Repeating
  the same input resumes its staging checkpoint, then retries pending/unresolved staged records.
- Stream input with an 8 MiB per-line ceiling, stage in batches of up to 100 rows/4 MiB, and commit each batch plus
  line checkpoint atomically. Staging allows 60s per SQL statement and 120s per transaction,
  scoped to that transaction; API limits remain unchanged. Resume gzip by rescanning/skipping
  the committed prefix.
- Stage only; do not publish records until EOF and file fingerprint verification. Changed input
  clears its untrusted staged prefix before retry. Invalid lines
  are quarantined with line number and diagnostic; unknown record types are not applied.
- One importer holds a catalog-wide session advisory lock. Canonical writes run sequentially in
  transactions defaulting to 25 records/4 MiB (configurable with bounded positive integers). Failed groups roll back before individual retries isolate bad
  records. A process/DB failure releases the lock and a repeat command safely retries.
- Distinct new authors, works, and editions use bulk inserts for metadata, relationships, mappings,
  outbox events, and outcomes. Mixed groups bulk-write new entries and guard mapped entries individually.
  Repeated source keys retain ordered application. Editions with absent/ambiguous work references use
  the existing placeholder/unresolved path. Bulk failures roll back before individual fallback.
- Failure logs name the actual sequential record, or the bulk operation and group boundaries without
  attributing a group failure to one record. INVALID/CONFLICT retain JSON and diagnostics for review;
  UNRESOLVED is retried, while operational failure leaves rolled-back records pending/unresolved.
- Importer connections allow 60s per SQL statement; canonical transactions allow 120s.
  Batch reads and whole canonical transactions retry statement timeouts, deadlocks, and serialization
  failures up to three total attempts with 1s/2s backoff. Individual exhaustion exits 1 and preserves resume.
  Retry/failure diagnostics identify the operation, cursor or record, elapsed time, and error code.
- ImportRecord uses table-specific vacuum thresholds (25000 + 0.005 × estimated rows) and
  analyze thresholds (25000 + 0.01 × estimated rows); throughput/latency need production verification.
- Read attempts log start/completion/failure for pending IDs, unresolved IDs, and payloads, with a
  shared readId, phase duration/count, cursor, and SQLSTATE on error, even if no page completes.
- Select staged runs first. Within each kind/run, read a bounded candidate page per status (default 50 IDs)
  using `(runId, kind, status, id)`, merge by UUID, then fetch a row/byte-bounded payload page in chunks of at most eight records.
  Defaults are 50 rows/8 MiB per page; a larger valid record is processed alone, never skipped.
  One cursor across both statuses prevents repeated unresolved records within that pass.
- Apply authors, then works, then editions. Missing authors do not block publication: omit unknown credits and keep the record
  UNRESOLVED for retry. A single missing work reference creates an explicitly incomplete work using
  the edition title and the real source work ID; later work metadata upgrades that same UUID.
  Editions with zero/multiple works still need review. Retry uses additive reconciliation and preserves editorial overrides.
- AVA UUIDs are stable through SourceMapping. Higher provider revisions enrich existing records;
  equal identical revisions and older revisions are skipped. Same-revision conflicts are quarantined.
- Each accepted update commits metadata, mapping revision/hash, record outcome, and CatalogOutbox
  event together. Entity revision changes identify outbox events; no consumers run in this milestone.
- Reimports fill missing scalar fields, append aliases/identifiers/subjects/credits, and add missing
  localized texts. Existing values and explicit admin corrections (including cleared values and
  removed relationships) survive. Different nonempty claims retain the current value and record
  CONFLICT with field names; other safe additions commit in the same transaction. Retain raw JSON
  for comparison through the operator-only conflict report. Editorial override markers are excluded
  from public author/work/edition responses. Equal identical revisions remain no-ops.
- Confirmed SourceMapping identities reuse the same work/author UUID across providers; no automatic
  title/ISBN identity merge. Metadata reimports never publish files or restore withdrawn assets.
  Works/authors remain automatically discoverable unless explicitly hidden.
- Normalize descriptions/biographies from string or value objects without guessing their locale
  (und fallback); retain author aliases and structured author links. Preserve unknown language codes;
  normalize common ISO-639 codes. First edition language/publisher is used; raw data retains all.
- Validate ISBN checksums and normalize ISBN-10 to ISBN-13. Invalid values stay in raw claims only.
  Resolve positive cover IDs to complete cover URLs and normalize reader categories from recognized subject labels. Keep raw labels
  and the category rule version; free-text contributors and exact dates remain raw metadata.
- Batch row/byte limits are configurable through CATALOG_IMPORT_READ_SIZE/READ_BYTES and
  CATALOG_IMPORT_TRANSACTION_SIZE/TRANSACTION_BYTES; invalid settings fail before applying data.
  Startup logs the effective settings. Each nonempty apply page logs payload bytes/RSS/heap alongside read/apply/transaction/write milliseconds, transaction attempts,
  fallback/bulk record counts, and processed-record throughput. Page timings include retry delays; transaction/write
  timings include failed attempts but exclude retry backoff.
- CLI prints run ID/checkpoint and record counts by status. Invalid/conflicting rows make exit code 2;
  unresolved relationships are reported but retryable. Operational failure exits 1.

## Acceptance criteria

- [x] Fixture authors/works/editions become linked catalog metadata without main API/DB access.
- [x] Replay/resume neither duplicates IDs nor emits duplicate change events.
- [x] Newer revisions enrich; old/equal-conflicting revisions and manual edits are preserved.
- [x] Missing dependencies resolve after later imports; corrupt gzip stays unpublished and invalid
      records cannot partially update an entity.
- [x] A second importer is refused while the first holds its lock; rollback keeps outcomes consistent.
- [x] Plain/gzip parsing, UTF-8, malformed records, oversized lines, and ISBN conversion are tested.

## Operations and limits

See [importer operations](../../catalog-import.md). Operators retain original files externally;
file acquisition/object-storage archival, source-specific retention automation, COPY-based scaling,
field-level multi-source assertions, and production corpus benchmarks remain future work.
