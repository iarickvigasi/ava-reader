# Explore · editorial controls

> Status: active · Updated: 2026-10-29 · Parent: [\_overview](_overview.md)

## Behavior

Admins use the ordinary Explore routes, work/edition details, author pages, and Read action.
Admin-only actions edit public works, editions and authors; publish or withdraw reading files;
correct edition/work links; and delete works. Ordinary browsing does not expose editorial actions.
Work info includes a representative edition summary and links to its edition details.
Edition-specific editing lives at /app/explore/editions/<editionId>, with a link to its owning work.
Covers prefer the edition image, then the work image, then another public Catalog edition image.
Private uploads and their covers/links never enter Catalog cover selection. Edition authors fall
back to work authors; other contributor roles remain distinct. Read/Listen use the selected edition.
Private upload links explicitly explain that only their owner can see them. Publication action rows
are per processed public reading file, on work and edition pages. Labels switch between Publish and
Unpublish after successful changes; localized captions explain current availability and what the
action changes. Pending synchronization is identified. Multiple files include their
title/language/filename; unfinished files cannot publish. Confirm through the existing modal. Choose
an existing upload through title/author search with at most 20 matching suggestions; editing the
search clears the selection, and saving requires choosing a suggestion. Edition editing localizes
its title, metadata fields, format choices, identifiers, source summary, and form actions/statuses
in every supported UI locale; catalog values remain unchanged. Descriptions prefer imported public
EPUB text, falling back to localized Catalog text. Draft descriptions remain admin-only. Author
labels use paired masculine/feminine forms where applicable; English retains neutral “author”.
Publish requires rights/quality confirmation for a processed reading copy, selecting an edition when
several are pending. No source file means publishing is unavailable. Reuse the normal Read button
for admin-only draft acquisition through the library bucket; other users cannot acquire drafts. The
first admin preview may create membership after checking admin access and the exact processed PUBLIC
copy; it must not require a pre-existing membership. The former /app/admin/reviews and
/app/admin/catalog indexes redirect to Explore; navigation uses the same destinations for admins and
ordinary users.

Edition/work correction changes the public grouping from the named current work to the selected
work. It does not relocate files or access private uploads/links; the dialog shows one confirmation
sentence naming the selected edition and target work only after both are chosen; omit empty
selection/status placeholders.

Edit opens prefilled title/name, language, cover, subjects/categories, localized text, contributors,
publisher/year/format, aliases/biographies, and identifier fields appropriate to the record.
Contributors show the selected person with an explicit Change action; search opens only when
adding/changing a person. Contributor roles are localized; existing credited names are preserved
without exposing an alternate printed-name field. Contributors can be removed or reordered;
reordering requires multiple contributors. Roles and order remain editable. System IDs, provider
provenance, file checksums, and source snapshots are read-only. Changing an edition language with an
existing reading asset requires importing a new copy. Edits increment revision so provider
reconciliation preserves editorial corrections. Conflicting concurrent edits fail with a reload
instruction; partial metadata changes roll back atomically.

## What Delete book does

Delete book means stop offering this book to new readers; it does not erase its files. The
confirmation names the book and explains that existing readers keep their copies. After
confirmation:

1. Main marks every associated public reading entry ARCHIVED. This means nobody can add those
   reading copies to their library through Explore, even from an old cached page.
2. Catalog marks the work deleted and its reading files WITHDRAWN. The book disappears from Explore
   results and author book lists; opening its old public detail URL returns not found.
3. EPUBs, covers, and processed reading files stay in storage. Anyone who already added a copy keeps
   access to it, including their reading position, highlights, notes, and offline downloads. Private
   uploads are untouched. Delete book does not reclaim disk space or perform a legal takedown.

Main and Catalog are separate backend services, so these steps cannot share one database
transaction. If Main archives the reading entries but Catalog is unavailable, the book may remain
visible for a while, but new readers cannot acquire it. The admin sees an error and must retry
Delete book to finish hiding the metadata. Imported-file withdrawal messages are also saved in Main
and retried automatically by its worker. Automatic withdrawal retry does not finish deleting the
work metadata. The UI reports success only after the Catalog deletion request succeeds.

## Authorization and data boundaries

Main API checks Clerk identity and the current admin role on every editorial read and mutation. It
signs a fixed, whitelisted Catalog operation. Catalog verifies the service signature before reading
private provenance or changing metadata; browser-supplied admin claims are never trusted. Draft
metadata/review responses are not persisted in public discovery caches. Existing cached role state
only controls button visibility. Actual access always requires fresh server authorization. Admin
mutations require connectivity; ordinary user reading retains existing offline behavior. After a
successful change, mounted Explore resources refresh without exposing review data publicly.

## Verification

Test admin versus ordinary-user visibility and permissions; unsigned Catalog requests; revision
conflicts; immutable imported language; soft deletion and acquired-copy preservation; normal Read
for drafts; publication confirmations; and editing localized metadata without changing provenance.

## Reviewed batch publication

The 300-title classics collection is authorized for publication before editorial review. Importing
stages and processes bytes, then publishes eligible collection copies with review deferred. Rights
research is retained; this policy does not record legal clearance or a completed quality review.
Admins may publish any processed public copy with review deferred, or complete the existing review.
Unpublish withdraws reading availability without deleting metadata; explicit admin publication
restores it. Importer replay must not restore a copy an admin withdrew. Failed processing never
publishes. All mutations use current admin authorization and durable signed synchronization; private
uploads stay private.
