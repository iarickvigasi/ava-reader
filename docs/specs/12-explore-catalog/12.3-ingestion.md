# Explore · sources and ingestion

> Status: active · Updated: 2026-10-23 · Parent: [\_overview](_overview.md)

## Researched source strategy (2026-10-10)

- **Open Library:** base catalog from monthly works, editions, authors, redirects, and deletes
  [dumps](https://openlibrary.org/developers/dumps). Use permitted API lookups only for targeted
  human requests: [guidelines](https://openlibrary.org/developers/api) reject bulk API harvesting
  and high-traffic backend use. Import to AVA; do not proxy every search to the provider.
- **Wikidata:** enrich linked author identities, multilingual labels, dates, and external IDs.
  [Structured data is CC0](https://www.wikidata.org/wiki/Wikidata:Licensing); images and Wikipedia
  prose carry separate terms. Use relevant subsets/dumps, not a full graph database in AVA.
- **Project Gutenberg:** future public-reading source. Use its machine-readable catalog and
  approved [robot/mirror channels](https://www.gutenberg.org/policy/robot_access.html), not ordinary
  page scraping. Catalog metadata is public domain; asset distribution needs separate review.
- **Google Books:** optional lookup/display enrichment after retention policy review, not the
  canonical permanent import. [API terms](https://developers.google.com/terms) restrict database
  building/permanent copies absent permission and permitted cache behavior.
- Future national-library, publisher, author-submitted, and licensed commercial feeds fill measured
  regional/new-release gaps. Goodreads-like UX does not require scraping Goodreads or its reviews.

Open Library's [licensing statement](https://openlibrary.org/developers/licensing) is not a blanket
license for every description/cover. Record policy per source and rights per asset/text assertion.
No provider guarantees universal coverage. Measure by language, period, genre, and edition format.

First adapter: [Open Library importer](12.6-open-library-import.md). The pipeline below is the target;
source policies, multi-source field resolution, deletes/redirects, and asset fetching remain deferred.

## Pipeline

1. Register Source policy: permitted fetch/storage/display/redistribution, attribution, rate limit,
   retention, and takedown handling; store policy/evidence URL and review date.
2. Acquire an immutable dump/feed snapshot into object storage with checksum and ingest manifest.
3. Stream parse into staging with run/checkpoint, external ID, source revision, and payload checksum.
   Use batch COPY/loading and bounded transactions; do not hold the dump in process memory.
4. Normalize dates with precision, languages, identifiers, credits, and localized text. Import
   authors/works before editions or stage unresolved relationships for a later reconciliation pass.
5. Resolve source IDs, generate match candidates, and apply allowed canonical field assertions.
   Each source key+revision is replay-safe; an older dump cannot overwrite a newer accepted record.
6. Commit canonical changes and outbox events together. Async workers update search projections,
   derived counts, CDN invalidations, and main-system metadata refresh feeds.
7. Record counts, errors, unresolved references, duplicates, merge decisions, and source coverage.
   Retry transient failures; quarantine bad records, with resumable checkpoints and manual review.

Keep competing field assertions; apply deterministic field-specific precedence (curator override,
trusted edition publisher, other approved sources). Missing fields are not deletions. Explicit source
deletes retract assertions/mappings, then recompute canonical fields; keep stable tombstones/redirects.
Policy retractions remove affected projections/assets and propagate via outbox. Retain raw records
only as policy allows. Audit changes and let operators undo a bad batch without dropping user links.

## Public-domain assets

CatalogAsset records edition, format, checksum, origin, retrieval date, rights basis, territories,
review status, and evidence. Unknown/restricted assets remain metadata-only. The original work,
translation, illustrations, and edition may have different rights. Gutenberg's
[permission guidance](https://www.gutenberg.org/policy/permission.html) describes US-based status;
do not infer worldwide availability. Rights and processing readiness are independent states.
EPUB bytes/derived packages belong in object storage/content delivery, not catalog PostgreSQL rows.
Catalog covers use asset-specific policy and CDN URLs; never inline base64 images in search results.
