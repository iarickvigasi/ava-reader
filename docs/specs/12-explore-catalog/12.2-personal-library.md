# Explore · personal library and uploads

> Status: draft · Updated: 2026-10-20 · Parent: [\_overview](_overview.md)

## Main-system ownership

Keep Clerk identity, collections, reading progress, annotations, AI output, and private files in
the main system. Catalog API receives no personal shelf or private file contents. Public read
routes need no per-request lookup in main DB; catalog administration uses protected staff routes.

Proposed UserCatalogBook: client ULID id, userId FK, catalogWorkId (opaque UUID), optional selected
catalogEditionId, metadataSnapshot, snapshotRevision, addedAt, archivedAt; unique (userId, workId).
Reading and wish lists are independent memberships, not an enum prohibiting multiple lists.
Generalize CollectionItem to target exactly one UserCatalogBook or existing LibraryItem, with
separate uniqueness constraints; catalog-linked reading copies use the saved-work target only.
Unmatched private imports can retain their current LibraryItem memberships during transition.

Add nullable userCatalogBookId FK and catalogEditionId to LibraryItem. Keep Book as the existing
content record; multiple private imports of one work may have different Book/LibraryItem IDs.
Preserve the current (userId, bookId) constraint. A metadata-only save creates no Book, LibraryItem,
ReadingProgress, or content blob. Reader access always selects an actual owned reading copy.
Counts distinguish unique saved works from reading copies and available offline content.
Completion remains per LibraryItem; saved-work aggregation must explicitly define multi-copy rules.

## Proposed contracts and failure behavior

- Catalog API: GET /works?query&language&cursor, /works/:id, /works/:id/editions,
  /authors?query&cursor, /authors/:id, /authors/:id/works, and /resolve for identifiers.
  Responses include revision and redirect resolution; bound result sizes and query complexity.
- Main API: idempotent save/membership mutations accept saved-work ULID and opaque catalog IDs.
  Validate ID/edition relationships when online; maintain last-good snapshots. Requests originating
  from already cached canonical results can queue offline; temporary catalog failure retries
  validation rather than permanently dropping the user's action or trusting arbitrary metadata.
- Apply personal mutations immediately through the library bucket, persist to per-user Dexie, and
  reconcile snapshots plus pending changes. Add versioned tables/queues with account isolation.
- Main API imports accept an optional target saved-work/edition; authorize its ownership and attach
  the new reading copy in the same main-DB transaction. No transaction spans both databases.
- Metadata refresh and redirect reconciliation run in batches/background. Catalog IDs are retained
  during outages/deletions; snapshots continue to render. When a merge creates duplicate saved works,
  union memberships and reassign copy links transactionally; retain mutation-ID aliases for replay.

## Linking existing uploads and EPUB matching

Implementation status and import-order dependencies: [12.11](12.11-import-order-and-linking.md).
Private-copy link/relink/unlink is implemented as a narrow LibraryItem link/snapshot. The saved-work
shelf model below remains proposed; linking does not create or move personal shelf memberships.

Every supported private upload can link to existing catalog metadata during import or later.
From an uploaded book, search/select a catalog work; from a catalog book,
choose an existing owned upload or upload a new file. Both directions use the same idempotent
main-API link mutation, checking user ownership and catalog work/edition consistency. Upsert the
saved work, attach the reading copy, and union existing memberships without duplicating shelf rows.
Relinking/unlinking preserves file bytes, LibraryItem IDs, progress, annotations, and memberships;
keep saved-work memberships on unlink and preserve copy access. Multiple copies may link to one
work; a catalog page lists only the current user's copies. Never publish private upload existence.

From a catalog page, the selected work is the user's explicit target. Extract ISBN, title, authors,
language, and publisher to suggest an edition. Conflicts require confirmation; never silently attach
an unrelated file. General imports suggest candidates using identifiers first, then title/credits/
language; uncertain matching remains private/unmatched and can be linked manually later.
Link correction changes description identity, not file bytes, LibraryItem IDs, or reading locators.
Do not replace a file in place: a new copy/revision needs explicit progress migration semantics.
Reject unsupported/encrypted EPUBs with a useful error; file purchase does not imply DRM support.
Private checksums can deduplicate within a user's uploads; never reveal another user's possession.

## Public reading and migration constraints

Catalog records rights-qualified availability; main content pipeline fetches/normalizes an approved
shared asset asynchronously, with idempotent asset+checksum identity. Main authorizes access and
creates a LibraryItem once ready. Catalog and search never serve private EPUBs or reader packages.
Existing LibraryItem/Book IDs, sessions, annotations, offline cache keys, and source bytes stay intact.
The current source CATALOG must stop implying public domain; future smart shelves use actual rights.
Implementation must revise existing library specs and payloads; this draft changes no shipped contract.
