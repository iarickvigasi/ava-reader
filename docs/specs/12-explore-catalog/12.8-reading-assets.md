# Explore · approved reading assets

> Status: active · Updated: 2026-10-27 · Parent: [\_overview](_overview.md)

## Scope

Readable editions reuse the main published-content pipeline; metadata never grants file access.
The curated EPUB importer supports a bounded pilot; broad ingestion remains future production work.

## Ownership and behavior

- Catalog ReadingAsset belongs to an edition. Store source URL, checksum, format, provider rights
  statement/evidence URL/jurisdiction/review timestamp, readiness, and an opaque main catalog-entry
  ID. Catalog PublicBlob stores public EPUB, cover, metadata-snapshot, and reader-package bytes.
  Public-file reads use a transaction-scoped 45-second SQL limit; metadata queries keep 5 seconds.
  No user records, main Prisma client, or cross-database foreign keys live in Catalog.
- Pending or withdrawn assets never satisfy Available to read. READY requires an existing published,
  processed main reading copy; publisher/metadata presence or EBOOK format is insufficient.
- Match language and availability on the same edition. Work details show approved ready assets,
  their edition language, provider attribution, and rights scope. No claim of worldwide clearance.
- Read uses the existing authenticated main catalog-add endpoint through the library bucket;
  it is idempotent per user/book. Hydrate private metadata before opening the existing reader.
  Acquisition has a 30-second deadline; leaving the detail page cancels it and prevents late navigation.
  Timeout/failure re-enables Read for retry. First acquisition needs a connection; acquired/downloaded copies keep existing offline behavior.
- Main API continues to authorize publication and user ownership. Stale/unpublished asset pointers
  fail safely and never grant access to private uploads. Public acquisition must never reuse a
  private Book, cover, or metadata by title/author matching. Catalog browse never calls main API.

## Public cover bridge

GET /api/reading-assets/covers accepts up to 20 comma-separated entryIds and returns
{ items: [{ entryId, coverImageUrl }] } for READY assets only. Resolve the owning work cover
with the same edition fallback/order as Explore. Missing/unready mappings yield no item.
The main Home payload uses this public mapping; it never falls back to Book cover blobs.

## Availability synchronization

Imported-copy publication and withdrawal commit a durable pending flag and monotonic revision.
Signed receipts update Catalog availability; the main worker retries failed deliveries after restart.
Explore exposes READY only after synchronization; main acquisition authorization remains mandatory.

## Acceptance

- [x] Available to read returns the work; mismatched-language and pending assets do not match.
- [x] Repeated Read creates no duplicate book or library item and preserves annotations.
- [x] Metadata-only books remain browseable with no fabricated Read action.

## Curated classic EPUB importer

Implemented CLI: apps/catalog/src/reading-import. Main boundary:
apps/api/src/catalog/reading-import. Storage and authorization decision: [ADR 12](../../adr/12-classic-reading-import.md).
Commands, review schema, and deployment: [operations](../../catalog-reading-import.md).

- Ordinary inventory runs after authors/works/editions finish. Curated bootstrap can run first
  ([12.11](12.11-import-order-and-linking.md)); both lock Catalog metadata operations only. Ordinary inventory refuses
  unfinished runs, pending records, or no edition import. Report unresolved records;
  those editions are excluded rather than blocking completed, usable metadata indefinitely.
- Inventory performs no network requests and writes no DB rows. A curated title + credited-author
  shortlist uses full author names and original-language codes: 50 works each in Ukrainian,
  English, German, French, Spanish, and Polish. Each language has equal distinct women/men authors;
  seeds record editorial author gender, death year, and bibliography. Every language has 25 works by women and 25 by men.
  Optional --language filters inventory. Only the requested edition language matches; title aliases
  cover common catalog spellings.
  Seeds interleave languages and women/men works, with at most five links per seed and 100 total.
  Exact provider edition links supply IA item IDs; titles/authors are discovery filters, never
  cross-source identity or rights evidence. Missing titles/links/languages are reported or skipped.
  The bounded first inventory checks at most 100 editions per seed, not every edition in the corpus.
- Inspection fetches exact IA metadata and selects one unrestricted EPUB, requiring an exact
  filename if several exist. Reject lending/print-disabled/dark/private/encrypted files. Download
  at most 50 MiB, verify provider MD5 and length, compute SHA-256, and save the EPUB plus metadata
  snapshot in an operator-controlled review manifest. No publishing or ReadingAsset write occurs.
- Requests are sequential, identify AVA/contact via User-Agent, wait one second between requests,
  allow only approved HTTPS archive hosts/redirects, and use response-size/time/redirect limits.
  Retry throttling/server errors three times, honoring Retry-After; long delays exit for later replay.
- Publication accepts completed review or explicit admin authorization with review deferred: actor,
  jurisdiction, evidence URL, statement, dates, and notes. The operator reviews the translation,
  illustrations, completeness/volumes, and beginning/middle/end text against scans where available.
  Public access, old publication, a famous author, or an EPUB filename never implies permission.
- Before upload, revalidate the provider mapping/revision/language and current IA access/file digest.
  Changed catalog metadata requires a fresh inventory/review. Do not silently remap by title/ISBN.
- Main POST /api/admin/reading-imports uses existing Clerk admin authorization, validates the
  source hash, EPUB limits, and embedded language, then creates a fresh PUBLIC Book, DRAFT entry,
  source/cover blobs, and reader processing run. It creates no LibraryItem or reused private upload.
- Missing EPUB language may use `fileMetadata.operatorLanguageVerification`, bound to hash/language.
  Store TEXT_SAMPLES, notes and verifiedAt; conflicting embedded languages still fail.
- Main importKey identifies edition + SHA-256; retries/concurrent POSTs reuse the Book/run.
  Main keeps descriptors; source/cover/package bytes and raw IA metadata live in Catalog (ADR 13).
  Approval occurs at Publish; changed bytes get a new identity and never replace acquired packages.
  Upload requires no approval: it creates an unpublished draft for the admin review queue.
- GET on the same admin boundary reports PENDING, PROCESSED, FAILED, READY, or WITHDRAWN.
  POST /publish requires completed processing for this source, matching source checksum, navigation,
  at least five text paragraphs/1,000 characters, and no more than 0.1% replacement characters.
  These are conservative technical gates, not proof of literary/OCR accuracy; human approval is
  can follow publication. Restoration needs explicit admin authorization and valid processed bytes.
- The importer polls processing for up to 60 seconds. The 300-title classics policy then publishes
  with review deferred; other titles stay drafts. Replays preserve explicit admin withdrawals.
- Explore uses the same cards and details for everyone. Admins additionally see imported drafts,
  Read for processed drafts, and Publish/Edit/Delete controls. Publish collects rights/quality
  confirmation or deferred review in a modal; Read uses the library bucket and normal reader with admin-only draft access.
  [Editorial controls](12.10-editorial-controls.md) own modals/metadata edits and the legacy redirect.
- Explicit Publish records the authenticated admin, file checksum, rights basis/territories,
  evidence URL, and quality notes. Processing and technical quality gates must pass first.
- Main commits publication plus a durable sync-pending flag/revision, then pushes a signed,
  timestamped publication receipt to Catalog. Catalog validates edition provenance and rights;
  monotonic revisions reject stale events. READY is exposed only after Catalog acknowledges it.
  A main background worker retries missed deliveries after crashes; admin can retry the action.
- Imported-entry withdrawals through the existing admin catalog also enqueue synchronization.
  Publication failure remains visible as pending synchronization; it is never reported as complete.
  No cross-database access occurs. HMAC credentials are required on both services and never exposed
  to the browser. Existing acquired copies retain access under ADR 11.

## Import verification and limits

- [x] Restricted/encrypted/ambiguous files, missing approval, changed bytes, and bad encoding fail safely.
- [x] Unfinished metadata is refused; complete metadata with unresolved unrelated rows is reported.
- [x] Processing stages a draft; collection policy may publish it with review deferred.
- [x] Preview is admin-only and uses the existing reader; Publish synchronizes Explore with retry.
- [x] Unprocessed/poor-quality/private copies cannot satisfy READY; restoration needs explicit authorization.
- [x] Only signed publication delivery changes availability; the CLI has no reconciliation writer.
- Server operators use scoped signed internal import/status/publication requests without Clerk (ADR 14).
  Browser admin/private routes retain current authorization. Verify manifest digest and EPUB checksum.
  Operator actions are audited as server-operator; replay never restores withdrawals.
  The original texts pass a conservative life-plus-100-year screen as of 2026; this is not
  worldwide edition clearance. [Rights audit](../../catalog-classics-rights.md) records the limits.
- Explicit IA, Standard Ebooks and Wolne Lektury IDs are supported; Gutenberg/Wikisource need adapters.
- A worker crash can leave processing stuck at PROCESSING; automatic job lease recovery is missing.
- Before broad rollout: storage/backup capacity measurement, external-provider policy reconciliation,
  launch-territory enforcement. Jurisdiction is currently
  recorded/displayed, not enforced by geographic access controls. Scope this pilot accordingly.
- Embedded covers fill empty edition covers and Explore; public images require an attached, visible work.
