# Explore · approved reading assets

> Status: active · Updated: 2026-10-23 · Parent: [\_overview](_overview.md)

## Scope

Readable editions reuse the main-system published-catalog/content pipeline. Catalog metadata alone
never grants access to a file. Source ingestion and availability reconciliation require separate
production work; this contract contains no localhost fixture or book-specific import steps.

## Ownership and behavior

- Catalog ReadingAsset belongs to an edition. Store source URL, checksum, format, provider rights
  statement/evidence URL/jurisdiction/review timestamp, readiness, and an opaque main catalog-entry
  ID. No file bytes, user IDs, main Prisma client, or cross-database foreign keys live in catalog.
- Pending or withdrawn assets never satisfy Available to read. READY requires an existing published,
  processed main reading copy; publisher/metadata presence or EBOOK format is insufficient.
- Match language and availability on the same edition. Work details show approved ready assets,
  their edition language, provider attribution, and rights scope. No claim of worldwide clearance.
- Read uses the existing authenticated main catalog-add endpoint through the library bucket;
  it is idempotent per user/book. Hydrate private metadata before opening the existing reader.
  Acquisition has a 30-second deadline; leaving the detail page cancels it and prevents late navigation.
  Timeout/failure re-enables Read for retry. First acquisition needs a connection; acquired/downloaded copies keep existing offline behavior.
- Main API continues to authorize publication and user ownership. Stale/unpublished asset pointers
  fail safely and never grant access to private uploads. Catalog browse never calls main API.

## Availability synchronization (planned)

Main publication changes do not automatically change Catalog READY status. Reloading Explore reads
Catalog again, so a main-only unpublish remains advertised until Catalog is updated. Publish main
status changes through an outbox to a retryable Catalog consumer that withdraws or rechecks assets.
A periodic reconciliation job repairs missed events; the main authorization check remains mandatory.

## Acceptance

- [x] Available to read returns the work; mismatched-language and pending assets do not match.
- [x] Repeated Read creates no duplicate book or library item and preserves annotations.
- [x] Metadata-only books remain browseable with no fabricated Read action.
