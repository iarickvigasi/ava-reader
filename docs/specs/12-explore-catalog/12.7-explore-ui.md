# Explore · browsing and shared book details

> Status: active · Updated: 2026-10-25 · Parent: [\_overview](_overview.md)

## Goal and current gaps

Explore browses canonical works with immediate filters, search, and pagination. Library and Explore
compose shared book presentation independently. Book/edition details and author pages are implemented;
personal saves and upload links remain later milestones. Reading assets follow [12.8](12.8-reading-assets.md).

## Explore and navigation

- `/app/explore`: search title, author names/aliases, or ISBN; language filter; paginated results.
  Empty query browses all canonical works through bounded pages, without recommendations.
- Reuse the Library search-field primitive and card. Filter pills apply immediately and toggle
  independently with aria-pressed. Use the categories and scrolling rows in [12.9](12.9-reader-categories.md), plus a separate language row; remove
  completeness/identifier/edition-count and bibliographic-format pills. Languages combine with OR;
  availability combines with AND and must match the same edition as language.
  Reset accumulated results on search/filter change. Measure responsive grid/viewport for an initial
  screen of cards; append another screen when the bottom sentinel enters view. Keep loaded cards
  during requests, deduplicate work IDs, prevent overlapping loads, and stop at the last cursor.
  Errors retain earlier cards and offer retry; provide a Load more fallback. Resize changes the next
  batch size without discarding loaded results. API batch limit is 1–40 (default 20).
  Available to read requires an approved ready asset; see [12.8](12.8-reading-assets.md).
  Metadata existence, ebook format, or an Open Library record never implies readable content.
- Return one card per work, with title, author links, and cover fallback. Reuse library card
  presentation without requiring a LibraryItem or reading progress. Card titles use compact type;
  Loading matches the same header, search, two mobile pill rows, language row, and responsive grid.
  Placeholder titles use smaller type and truncate after five lines. Show author names beneath
  the card title, with a localized unknown-author label when credits have not arrived.
- Debounce typing, cancel superseded requests, cap input/page sizes, and preserve query/filter/page
  navigation state, including accumulated pages and a visible-card scroll anchor on return from details. Show loading, no results, retryable failure, and offline states separately.
- `/app/explore/books/[workId]`: work details with Library-style typography and cover layout. Show representative edition
  author and Read action directly below the title, then edition language, format, year, and approved rights. Read/Listen use that selected edition. An edition-details link sits left of Read with a 1.5rem gap; edition controls are on a separate page.
  Startup and uncached loads share a book-detail skeleton below clickable app navigation; edition metadata remains below Read, without edition cards.
  Work and edition info use the processed public copy for Library-style page/time estimates. Missing counts show Unknown. These
  fields exclude personal minutes/progress; unpublished estimates require admin authorization.
  Metadata and estimates share two aligned columns with wider gaps. Never show browse-loading text here.
  No Previous/Next buttons; representative editions are not first editions.
- `/app/explore/editions/[editionId]`: public edition metadata/credits, admin edition controls,
  and a back link to its owning work. Generic shell/cache behavior matches work details.
- `/app/explore/authors/[authorId]`: name, biography, and accumulated credited works with Load more.
  Hide source aliases; show safe HTTP(S) biography references as localized Source links.
  Use shared back-link typography and a dedicated author-route loading boundary with the author/works skeleton below clickable navigation.
  Identify contributor roles; edition-only credits must not become work authorship.
- Private uploaded copies and their catalog links stay on `/app/library/books/[slug]`.

Reuse existing typography and BookCover; never fabricate copy IDs for catalog payloads.

Keep owned-copy statistics, annotations, offline saving, completion, deletion, and collections in
Library wrappers. Catalog pages never subscribe to copy-specific state. Share metadata layout and
formatters; personal minutes-read composition stays in Library. Preserve description sanitization
and existing reader-link interception.

publication format. Publication year belongs to the selected edition, not the work's first release.

## Bounded browsing

Share Library’s centered illustrated states; errors show one Retry; hide the end footer without books.

Render visible responsive rows plus two overscan rows on each side; keep the focused row mounted.
Use bounded cover frames and clamped card text for predictable row sizing. Keep five result pages,
with one temporary extra page when focus prevents eviction; pause automatic paging at that bound.
Fetch earlier pages through a before cursor. Evict distant pages and preserve a stable work/row
anchor on append, prepend, resize, and return from details. Navigation snapshots share these bounds
and expire after 30 minutes; persisted public response caching remains capped at 40 entries.

## Personal actions: subsequent milestone

Implement [12.2](12.2-personal-library.md) before enabling saves or attachment controls:

- Add to reading list and Add to wish list are independent, persistent memberships without a file.
- Upload EPUB attaches a new private copy to the work and confirmed edition. Link existing upload
  opens only the current user's copies; the existing library page offers the inverse link action.
- Owned-copy section offers Read/Continue, or a copy chooser when several copies exist. Read opens
  a ready copy; uploaded/processing/failed states give accurate status. Catalog metadata alone never
  produces a reader link. Future public reading requires an approved asset and processing pipeline.
- Main API/buckets own personal status and mutations; obtain batched status for visible work IDs,
  not one main-API request per result. Public catalog responses contain no personal status.
- Linked library pages retain file metadata and reading state, with a distinct catalog-details
  section; metadata refresh must not overwrite private import metadata or estimated reading data.

## API, caching, and offline boundaries

Catalog API exposes `GET /api/works?query&languages&filters&cursor&before&limit` with compact cards.
Search title variants, author names/aliases, and normalized ISBNs using indexed PostgreSQL;
Filter language on the matched edition; apply [12.4](12.4-rollout-and-search.md) benchmark gates.
Initial browse/search queries canonical tables with indexed case-insensitive substring matching
and exact normalized ISBN lookup; UUID cursor order is stable, not relevance-ranked. Bound input,
page size, language selections, and DB statement time. Rebuildable projections and relevance ranking
remain the next scaling milestone; no claim of global-corpus performance is made.

Use a dedicated catalog client/base URL and gateway/CORS configuration; browser discovery requests
bypass main API. Production uses same-origin `/catalog/api`; the gateway strips `/catalog`.
Cache public responses in per-user Dexie meta: at most 40 entries, 512,000 characters per entry;
SW bypasses `/catalog/api/*`; no whole-catalog sync. `/api/works/filters` returns ≤200 language codes.
Saved snapshots and personal mutations stay in the per-user library bucket. Include new caches in identity cleanup; cached content refreshes silently; failures retain retry feedback.
Book detail routes follow existing shell/hydration conventions; uncached offline pages show a useful
unavailable state. Catalog outages must not prevent opening existing library copies.
