# Bilingual · phrase alignment and selection

> Status: active · Updated: 2026-09-23 · Parent: [_overview](_overview.md)

## Behaviour

- Mouse hover and short tap/click in either column highlight the corresponding phrase in both
  languages. The warm yellow overlay follows the light/dark theme and never alters text layout.
- A tap on the same phrase or empty space clears the highlight; another phrase replaces it.
- Alignment takes priority over text links and annotation clicks. Saved highlights and AI-comment
  underlines are not painted in bilingual mode. They remain stored and visible in the normal reader.
- Long press begins selection; dragging extends it; release opens the AI toolbox. Mouse selection
  and double-click retain the same panel flow. Exact matching saved comments reopen in the panel.
- Both columns support selection. Each column uses its own language for iOS word/grapheme units.
  Translation selections keep separate sentence offsets and translation identity in the locator;
  its outer source anchor refers to the original sentence(s), never translated character offsets.
- Translate defaults to the reading language for original text, and to the book language for
  translated text. A visible target picker permits an override. Unknown or identical book language
  requires a target choice; do not request a same-language translation of translated text.
- Starting selection, navigation, opening a panel, cancellation, or layout change clears alignment.
  Movement before the long-press threshold belongs to page navigation, never a short alignment tap.

## Generation and persistence

POST `/library/:id/translations/align` uses the existing authenticated translation request identity
and sentence ownership checks. It reads persisted translations; it never rewrites or regenerates
them. The server segments exact text into numbered tokens and asks AI for correspondence groups.
One-to-many, many-to-many, reordered/discontinuous phrases and unmatched tokens are supported.
Invalid IDs, duplicate membership, missing sentence IDs, or partial model output are rejected before
storage. Code converts token IDs to UTF-16 ranges; the model never counts character positions.

`SentenceTranslation.alignment` stores version 1, exact source/translation text and range groups.
Chapter GET includes saved maps; the existing per-user Dexie chapter cache persists them. Text,
revision, language, or alignment-version mismatch invalidates a map. Alignment failures leave the
translation readable, and the footer retry retries alignment separately from translation.

Demand starts with visible translated sentences, then up to eight upcoming sentence candidates,
in batches of at most eight and 16,000 combined characters. It generates no missing translations
and no whole-book alignment job. Navigation/unmount/hidden/offline stops demand; completed maps are
reusable offline. Hover/tap only reads local maps. Unmatched words or unavailable maps show no
invented correspondence. Oversized sentences outside the current batch limit remain readable
without alignment.

## Validation

Unit coverage includes token validation, discontinuous groups, Unicode, cached generation, stale
text invalidation, offline reuse, overlapping requests, language direction, synthetic mouse events,
and saved-comment language isolation. Browser fixture tests exercise both columns and the iOS
selection path under emulation. Physical iOS Safari and Android selection/callout QA remains required.
