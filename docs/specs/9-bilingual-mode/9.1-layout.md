# Bilingual · layout and sentence pagination

> Status: active · Updated: 2026-09-22 · Parent: [\_overview](_overview.md)

## Behaviour

1. Separate effective mode from activePanel. Desktop uses session state; phones derive it from
   screen orientation. Detect phones independently of current viewport width so rotation does not
   switch them to desktop chrome. Keyboard/browser bars must not toggle mode.
2. Reuse the ordinary reader's font sizes, book/author/chapter header, page width, and spacing.
   Sentences flow together inside their original paragraphs, lists, headings, and blockquotes.
   Both columns contain the same sentence range and flow independently; never add sentence rows
   or pad source paragraphs to match translation heights. Page boundaries fit both languages.
3. For a pair taller than the page, measure horizontal continuation columns independently for both
   languages. Render successive continuations together; a shorter side is blank once exhausted.
   Page counts come from measured DOM geometry, never character-count estimates.
4. Images need no AI; display source imagery locally and include its height in pagination.
5. Missing translations show skeletons in their place, with the original remaining visible.
   Initial preparation uses skeletons on both web and phone, without visible loading text.
   Keep localized offline/error status and use source measurements to allow navigation.
   Each arriving sentence updates the existing page without blinking or unmounting either column.
   Commit translated text and its measured layout together around the current source anchor;
   do not let background prefetch move the current page.
6. Source sentence content retains its inline formatting and absolute source offsets. Translation
   text never becomes an original-text locator. Sentence IDs are independent of layout dimensions.
7. Rotation/font changes clear selection and gestures, then measure again at the new dimensions.
   Preserve the original sentence/offset and settle layout before scheduling further generation.
8. Left swipe/ArrowRight advances; right swipe/ArrowLeft goes back. Disable gestures during panels
   and active selection. Page turns include chapter boundaries and never vertically scroll.
9. Phones retain compact controls and vertical spacing regardless of landscape viewport width.
   In landscape the phone header becomes a narrow vertical strip on the left short edge, with
   upright icons stacked vertically. Portrait restores the compact horizontal header.

10. Footer regeneration buttons show “Translating” and “Creating matches” while their respective
    visible-page content is being generated, automatically or manually. Reuse PendingLabel and its
    animated dots, without literal ellipses. Disable duplicate actions while busy. Upcoming-page
    prefetch alone does not show progress; completion, failure, and cancellation clear it.

## Measurement and demand

Measure flowing original and translated paragraph fragments with the same typography as the reader.
Fit the longest common sentence range on each page and find the first missing sentence.
Generate that sentence, measure it, and continue only until those pages are filled. Reuse completed
sentences anywhere in the chapter without translating preceding skipped sentences.
Cached range measurements include sentence identity: replacing a catalog after correcting the book
language must not reuse geometry for different sentences at the same numeric positions.

## Acceptance criteria

- [x] Desktop typography, book title, and paragraph flow match the ordinary reader.
- [x] Phone landscape uses the compact vertical header without desktop vertical padding.
- [x] Columns stay mounted; measured page boundaries update around the current source anchor.
- [x] Missing text and initial preparation use skeletons on desktop and phone.
- [x] Unit coverage includes short/long translations, images, Unicode, lists, and continuations.
- [x] Source ranges retain correct block offsets across inline and list boundaries in unit tests.
- [x] Simulated rotation in both directions preserves location; request identity tests reject stale
      results, and device tests distinguish physical orientation from viewport resizing.
- [ ] Physical iPhone Safari: rotation and browser-bar changes never truncate content.
- [ ] Physical iPhone Safari: rotation during swipes/requests preserves position and content.
- [ ] Physical iPhone Safari: keyboard/address-bar changes never auto-toggle bilingual mode.

Manual fixture checks on 2026-09-21 verified desktop/phone layouts, rotation, cache re-entry, and
six arrivals with no column remounts or vertical overflow. Playwright and physical checks are pending.

## Platform references

[Screen Orientation](https://www.w3.org/TR/screen-orientation/) describes screen rotation.
[Media Queries](https://www.w3.org/TR/mediaqueries-4/#orientation) describes viewport proportions;
keep this distinction in orientation fallback handling.
