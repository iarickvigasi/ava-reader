# Bilingual · offline cache and demand

> Status: active · Updated: 2026-09-22 · Parent: [\_overview](_overview.md)

## Data and sync

Add a translations cached-read bucket and versioned Dexie table. Cache the canonical chapter
catalog plus completed translations. Scope by user/library item/chapter/language/revision/version.
Use bucket subscriptions and existing authenticated API conventions; UI components never own fetch.
Persist completed sentences immediately. Keep loading/errors and generation demand ephemeral.
The per-user table key is [libraryItemId, chapterId, targetLang]. Each row stores the catalog,
revision/version, and sentence-ID-to-translation map. Languages coexist; a newer revision replaces
that language's local chapter row. Merge only matching revision/version identities.

## Scheduling

1. Read the complete cached chapter from IndexedDB first and display saved sentences immediately.
   On each chapter/language activation and reconnect, fetch all saved chapter translations from
   the database with GET. Merge and persist that response together, without AI generation.
   A local miss must await this GET before AI is allowed; never generate while it is pending or
   after it failed. Recheck missing sentence IDs after the bulk response arrives.
2. Measure flowing source and translated paragraphs. Starting at the current source anchor, request
   only the first missing sentence needed to fill the current and following bilingual page.
3. After each completion, merge/cache the result, measure again, and stop when the two pages fit.
   A page-boundary lookahead sentence is reusable on the following page.
4. At chapter end, preload enough of the following chapter to fill the one following page.
5. Navigation replaces demand; promote matching work, cancel obsolete requests, and never keep
   a durable queue of every page visited. Going offline pauses requests; reconnect considers only
   current demand. Hide/unmount/mode-off stops generation while preserving completed cache.
6. Display cached translations offline. Missing translation uses skeletons and localized
   offline/error status; allow source navigation. Retry only while the sentence is still wanted.
7. Font/viewport changes remeasure paragraph flow and reuse sentence IDs. Language switches load the
   matching cache. Old requests may complete only into their own version/language cache.

## Lifecycle

Add the new bucket to runtime reset on sign-out/account switch. Capture user/DB identity at request
start and verify it before publishing or persisting. Original book cache eviction does not erase
paid sentence translations; account wipe clears all local data. Server records remain reusable.
Handle storage failure without losing the on-screen completed result or blocking ordinary reading.

## Acceptance criteria

- [x] Reload/offline reopen returns completed translations without AI generation.
- [x] A slow database GET blocks generation, and a failed GET never falls through to AI.
- [x] Reopening merges all database translations at once before generating remaining misses.
- [x] Current/next demand is bounded and skipped pages are not replayed on reconnect.
- [x] Concurrent matching sentence requests coalesce and completed results merge safely.
- [x] Font changes, rotation, and page regrouping keep all compatible sentence cache hits.
- [x] Language/account switches never publish stale results into the active reading surface.
- [x] Incomplete or aborted client responses never enter the local cache. Complete server commits
      remain reusable even if the client disconnects before receiving them.
- [ ] Add a migration regression test verifying Dexie version 3 → 4 retains existing user data.
