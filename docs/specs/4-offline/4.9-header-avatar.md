## Summary

Keeps the app-shell header's avatar slot always occupying its fixed space — online, offline, or
mid-load — and caches the profile photo so it renders from Dexie instead of Clerk's own
(network-dependent) `<UserButton>` image when offline.

## Scope

- In: the avatar slot in the app-shell header (mobile + desktop bars); caching the photo bytes; an
  initials fallback.
- Non-goals: account management without connectivity.

## Behaviour

1. The header always renders a fixed-size (`size-8`) circle in the avatar slot: the cached/network
   photo if available, else the user's initial in a colored circle. Never blank, never the browser's
   broken-image icon.
2. `UserMenuButton` uses an app-owned, keyboard-accessible menu, available even when Clerk fails
   to initialize. It always retains the same cached-avatar component rather than swapping it out.
3. Explicit sign-out works locally while offline, warns about unsynced changes, and retries server
   revocation on reconnect ([[7-auth]]). Manage account is available when Clerk is loaded; otherwise
   the menu offers sign-in. Session expiry never removes the cached avatar or books.
4. Outside clicks/taps and pathname changes (including Back/Forward) close the account menu without
   blocking the outside control. Escape closes it and returns focus to the avatar. Manage account
   closes the menu before opening the profile. Inside interaction and avatar toggling still work.
5. The desktop profile chip is one menu trigger: clicking its name, avatar, or padding toggles
   the menu. Its name keeps the existing responsive visibility. Hover uses the theme button’s
   soft-tone fill, and keyboard focus has a visible ring. Mobile keeps the compact avatar trigger.
6. The desktop chip hugs short names with consistent padding and avatar spacing. Names are never
   truncated: beyond 12rem they wrap, including unbroken names. The desktop header grows vertically
   to contain the complete chip; the avatar stays fixed-size and responsive name visibility stays.

## Data & sync

Extends the `me` bucket (single-row, `apps/web/features/offline/buckets/me`): `CurrentUserRow` gains
`avatarBlob: Blob | null`, cache-first + lazy-write-through; cover bytes use a separate store (ADR 9)
([[4.1-offline-reading]]) — `readAvatarBlob`/`useAvatarBlobUrl` check Dexie first; a cache miss with a
network `avatarUrl` present triggers `persistAvatarFromNetwork` in the background. `applyCurrentUser`
preserves the existing `avatarBlob` across re-applies with the same photo URL (an online reload must not silently wipe the
cached photo). No new table/index, so no schema version bump.

## Edge cases

No `avatarUrl` (Clerk `hasImage` false) → initials only, no fetch ever attempted.
A changed or removed photo URL invalidates old bytes. Fetch fails
(offline/CORS) → swallowed, retried next mount or reconnect, no backoff. iOS 7-day storage wipe
([[4.1-offline-reading]]) applies the same as cover blobs — refetched lazily next time online.
Sign-out/account switch deletes the whole per-user database ([[4.7-data-isolation]]), so the cached
avatar goes with it.

## Acceptance criteria

- [ ] The app-shell header never shifts layout when the avatar is loading, offline, or fails to load.
- [ ] A previously-viewed profile photo renders from cache when opening the app offline.
- [ ] A user with no photo (or never-cached photo, offline on first-ever load) sees their initial in a
      colored circle, never a blank space or broken-image icon.
- [ ] An online reload never drops a previously cached avatar photo.
- [ ] Desktop and mobile menus dismiss on outside interaction, pathname changes, and Escape;
      Manage account closes the menu before opening the profile, including after offline use.
- [ ] The whole desktop chip toggles the menu, highlights on hover in both themes, and supports
      keyboard activation with a visible focus ring.
- [ ] Short names produce shorter chips; long and unbroken names remain fully visible without
      ellipsis, clipping, or header overflow.

## Avatar reliability update

- Current-user photos share a reactive cache across the header, Connect preview and own reader card.
- Initials stay visible until an image loads successfully, including slow/offline and failed loads.
- Cache writes notify mounted avatars; duplicate concurrent downloads are coalesced.
