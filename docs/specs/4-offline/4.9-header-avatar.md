## Summary

Keeps the app-shell header's avatar slot always occupying its fixed space — online, offline, or
mid-load — and caches the profile photo so it renders from Dexie instead of Clerk's own
(network-dependent) `<UserButton>` image when offline.

## Scope

- In: the avatar slot in the app-shell header (mobile + desktop bars); caching the photo bytes; an
  initials fallback.
- Non-goals: account management without connectivity.

## Behaviour

1. The header always renders a fixed-size (`size-8`) circle in the avatar slot: the cached/network
   photo if available, else the user's initial in a colored circle. Never blank, never the browser's
   broken-image icon.
2. `UserMenuButton` uses an app-owned, keyboard-accessible menu, available even when Clerk fails
   to initialize. It always retains the same cached-avatar component rather than swapping it out.
3. Explicit sign-out works locally while offline, warns about unsynced changes, and retries server
   revocation on reconnect ([[7-auth]]). Manage account is available when Clerk is loaded; otherwise
   the menu offers sign-in. Session expiry never removes the cached avatar or books.

## Data & sync

Extends the `me` bucket (single-row, `apps/web/features/offline/buckets/me`): `CurrentUserRow` gains
`avatarBlob: Blob | null`, cache-first + lazy-write-through exactly like `libraryItems.coverBlob`
([[4.1-offline-reading]]) — `readAvatarBlob`/`useAvatarBlobUrl` check Dexie first; a cache miss with a
network `avatarUrl` present triggers `persistAvatarFromNetwork` in the background. `applyCurrentUser`
preserves the existing `avatarBlob` across every re-apply (an online reload must not silently wipe the
cached photo). No new table/index, so no schema version bump.

## Edge cases

No `avatarUrl` (Clerk `hasImage` false) → initials only, no fetch ever attempted. Fetch fails
(offline/CORS) → swallowed, retried next mount, no backoff. iOS 7-day storage wipe
([[4.1-offline-reading]]) applies the same as cover blobs — refetched lazily next time online.
Sign-out/account switch deletes the whole per-user database ([[4.7-data-isolation]]), so the cached
avatar goes with it.

## Acceptance criteria

- [ ] The app-shell header never shifts layout when the avatar is loading, offline, or fails to load.
- [ ] A previously-viewed profile photo renders from cache when opening the app offline.
- [ ] A user with no photo (or never-cached photo, offline on first-ever load) sees their initial in a
      colored circle, never a blank space or broken-image icon.
- [ ] An online reload never drops a previously cached avatar photo.
