# Slow connection (degraded-but-online)

## Summary
Treats "online but not responding" as its own state, distinct from fully offline: a header badge
tells the user the connection is degraded while [[4.5-route-precaching]] §10 quietly falls back to
cached content for speed. Serves the offline-first job (product.md) — a slow connection shouldn't
feel worse than no connection.

## Scope
- In: a client-side `slow` signal driven by the SW's slow-fallback broadcast; a "Slow" header chip
  (yellow dot); the offline modal adapted to show connection-appropriate copy when opened from either
  chip.
- Non-goals: detecting slowness any way other than the SW's document-load timeout (no Network
  Information API — unsupported on iOS Safari, most of this app's traffic); a proactive/periodic
  connection probe; slow-connection handling for AI toolbox requests (independent fix, see
  [[5.2-ai-toolbox]] — deliberately not wired to this signal, kept simple).

## Behaviour
1. The SW broadcasts a `postMessage` to every open client each time `networkFirstDoc` falls back to
   a cached doc because the network didn't respond within its timeout ([[4.5-route-precaching]] §10).
2. The client's `slow-state` store (same subscribe/notify shape as `net-state`) flips `slow` true on
   that message and auto-clears it ~6s after the last message, so a burst of slow loads reads as one
   steady state instead of flickering on and off.
3. `header-chip-state`'s resolver takes `slow` as a new input, slotted right after `offline`: a truly
   offline device still gets the Offline chip, never Slow; otherwise Slow beats the priming/ready
   chip; otherwise unchanged (content → ready → nothing). Only one chip renders at a time, as today.
4. The chip renders as a compact "Slow" pill with a yellow dot (`SlowConnectionIndicator`), sharing
   its pill markup with `OfflineIndicator` via an extracted primitive so the two don't duplicate JSX.
5. Tapping the Slow pill opens the same offline modal used by the Offline chip, now carrying a
   `reason: "offline" | "slow"` so the dialog shows adapted copy ("your connection looks slow —
   showing cached content so the app stays responsive") instead of the offline copy. The modal never
   auto-opens for `"slow"` — only a tap does; unlike a real disconnect, a soft/transient state
   auto-interrupting the user would be noisy.

## Data & sync
No Dexie table, no persisted flag — `slow` is in-memory, client-side, session-scoped, and exists only
to drive the header chip. It resets to false on reload; nothing else reads it.

## Edge cases
A last slow-fallback message can land just as the connection actually recovers, so the chip can show
Slow for up to ~6s after things are fine again — accepted as self-correcting rather than adding
cross-module coupling (e.g. a SW "recovered" message) to clear it early. Genuinely offline while a
Slow signal is still decaying → no visible conflict, since the resolver checks `online` before `slow`.
Multiple tabs each get their own `slow-state` instance (the SW broadcasts to all clients, and each
client decays independently) — acceptable, since the badge is a per-tab UX cue, not shared state.

## Acceptance criteria
- [ ] The header shows a "Slow" pill with a yellow dot while online and a slow-fallback signal is
  active or recently was, and never shows both Slow and Offline at once — Offline always wins.
- [ ] The Slow chip yields to the Offline chip immediately on a real disconnect.
- [ ] Tapping the Slow pill opens the offline modal with connection-appropriate copy; the modal never
  auto-opens for the Slow state (only a real disconnect auto-opens it).
- [ ] A single slow-fallback event shows the chip for roughly 6s, then it clears on its own with no
  further signal.

## Open questions
Whether to extend the same signal to RSC/API data fetches beyond the current Dexie-first coverage;
whether a page already open during a slow fallback should live-patch once the deferred fetch lands,
instead of only benefiting the next load; whether AI toolbox slowness ([[5.2-ai-toolbox]]) should
eventually feed this same signal instead of staying independent.
